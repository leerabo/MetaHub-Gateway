## 统计口径

脚本扫描 196 个功能文件，其中 95 个渲染文件。当前词法命中为 1,873 处，渲染文件中的候选行为 725 处、566 行；这些数字不能直接等同于用户可见项：其中一部分是隐藏表单值、响应白名单、租户归属校验、路由选择、幂等键或审计字段。逐项判断以渲染模板和浏览器可见文本为准，不修改 API 合同来“消除”这些系统必需字段。

| 类别 | 系统是否需要 | 用户界面处理 |
| --- | --- | --- |
| `request_id`、`trace_id` | 需要，用于日志关联、错误排查和审计 | 普通状态、错误、用量和日志摘要不显示；仍保留在响应和客户端错误对象中 |
| `provider_id`、`provider_code` | 需要，用于租户隔离、路由、密钥池和幂等 | 使用模型服务名称；内部值仅保留为隐藏表单值和请求参数 |
| `model_id`、`internal_model_id` | 需要，用于路由、别名和权限校验 | 展示用户可理解的模型名称；不展示数据库 ID 或“内部模型 ID”标签 |
| `region_code`、`auth_type`、能力代码 | 平台目录和上游适配需要 | 普通组织设置不显示代码；只给必要的结果文案，例如“访问令牌已配置” |
| `revision`、`generation`、`cursor`、`fingerprint`、SHA-256 | 需要，用于 CAS、授权快照、迁移、签名和回滚 | 不进入普通用户表格、错误提示和配置表单 |

## 本轮代码调整

- 模型目录不再要求用户填写 MetaHub 内部模型名称，也不再展示“能力/上下文”高级字段；模型内部别名由厂家模型名称稳定生成，能力仍由后端保留并用于路由。
- 模型路由下拉只显示模型名称和模型服务名称，不显示 Provider code 或模型数据库 ID。
- 用量和调用记录不显示请求编号；筛选、导出和后端账本仍保留请求编号参数。
- 本地模型服务表不显示配置修订、目录修订和服务标识；创建时服务标识作为隐藏系统默认值提交。
- Provider 工程诊断只保留状态、优先级和规则数量，隐藏规则哈希、修订号和内部 Provider code。
- 调用日志详情把“错误诊断”“预算命中”“路由决策”“Fallback”等工程术语改成“失败说明”“预算检查”“模型选择”“备用模型重试”；模型服务错误处理只显示用户可理解的结果。
- 成本账本把 `debit/credit`、`Provider Usage` 和目标分录 ID 改成“扣减/增加”“模型服务用量”和“已选择当前分录”，筛选项也只显示中文业务标签。
- 审计筛选移除模型服务错误目录等内部对象选项，动作和对象全部使用业务名称；内部值仅保留为提交所需的不可见 option value。
- 全局用户文案守卫继续在异步重绘后清理请求/追踪号、内部 ID、错误码、版本和哈希；系统状态对象、日志和 API 响应不被清理。

## 未删除的系统字段

这些字段仍由后端和前端状态层使用：租户/Workspace 所有权、权限快照和指纹、模型与 Provider 路由目标、幂等键、CAS 版本、审计关联号、迁移/签名摘要、游标和回滚代次。删除它们会破坏撤权、跨租户隔离、并发更新、故障归因或审计追溯，因此本轮只收窄用户投影。

## 相关页面重设计

本轮同时按中文组织管理员的实际任务重做了相关入口：

- “添加模型服务”现在只有一个入口；品牌服务和“自定义中转站 / OpenAI 兼容”都在同一个选择框中。迁移参考条目不再混入组织管理员可接入目录。
- Provider 列表只保留模型服务、服务地址、状态、最近检查和操作；“类型”“Provider code”“兼容与错误规则”不再占用普通列表空间。
- 模型目录只保留显示名称、模型服务、模型名称、计价和状态；“MetaHub 模型名称”“能力”“上下文长度”等高级配置不再要求普通管理员填写。能力仍由目录和后端路由判断。
- 模型路由下拉显示模型名称和模型服务名称；备注示例改成普通业务语言，不再出现迁移、内部别名或工程代号。
- Provider 工程和异常处理仍然存在于系统内部，但组织页面只看到“服务状态”；高级异常处理仅对有管理权限的角色按需展开。

这些调整是用户投影收敛，不是删除后端合同。Provider/model ID、权限快照、CAS 版本、审计关联号和签名摘要仍必须留在 API、状态层和不可见提交字段中，用于路由、撤权、并发控制和审计。
