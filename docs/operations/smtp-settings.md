# 邮件服务配置

从 v2.0.0-trial.49 起，具备 `platform.operator.manage` 权限的 SaaS 管理员可在平台工作台的 **品牌与通知 → 邮件服务** 配置 SMTP。该配置按部署环境生效，用于注册验证、邮箱验证和密码找回。

1. 填写 SMTP 服务器主机名、端口、加密方式、登录账号、密码或授权码、发件邮箱与超时时间。仅支持验证证书的 STARTTLS 或 TLS。端口和账号格式以邮件服务商说明为准；部分邮箱使用专用授权码。
2. 保存配置。勾选“启用验证码邮件发送”后，新发送的验证码会立即使用已保存配置，无需重启。
3. 点击“测试连接与认证”，检查服务器连接、加密及账号认证，此操作不会发送邮件。
4. 输入自己可接收邮件的地址，点击“发送测试邮件”。成功提示仅表示 SMTP 服务器接受邮件，还应确认收件箱或垃圾邮件中收到邮件。同类测试间隔至少 10 秒。
5. 确认发信正常后，在 **操作员 → 注册验证设置** 开启邮箱验证要求。启用邮件发送本身不会改变注册验证要求；MFA 仍需单独手动启用。

常见配对是 **465 + TLS** 或 **587 + STARTTLS**。修改为这两个端口时，界面会选择对应的加密方式；保存和测试也会检查是否配错。使用 Gmail 密码认证时，应填写 Google 账号生成的应用密码，而非网页登录密码。

发送测试邮件后，收件地址会保留，便于失败后重试。测试失败只显示失败结果；注册时遇到 SMTP 连接、认证或投递故障会提示“验证码邮件暂时无法发送”，不会误报为“尚未配置”。

登录账号、密码和其他 SMTP 参数均以加密形式保存在数据库中。API 不返回密码，界面只显示是否已保存；修改非敏感参数时，密码留空会保留原密码。更换主机或登录账号时，必须重新输入密码，以免原凭据被发送到新的服务器。保存使用修订号校验，冲突时须刷新配置后重试。写操作要求平台会话、同源请求及 CSRF 验证。

首次通过网页保存前，继续使用原有 `METAHUB_IDENTITY_CHALLENGE_DELIVERY_MODE`、`METAHUB_SMTP_*` 环境配置。网页保存后，以数据库中的配置为准；取消启用后，不会退回环境变量继续发信。即使未启用验证码发送，也可以测试已保存的 SMTP 配置。

SMTP 密文使用部署的 `METAHUB_IDENTITY_PII_ENCRYPTION_SECRET` 派生密钥。备份和迁移时，应同时保留数据库以及受保护的运行时密钥；只恢复数据库而丢失此密钥，将无法解密 SMTP 配置。不得把运行时密钥或 SMTP 凭据上传 GitHub。

连接失败时检查地址、端口及服务器出站网络；加密失败时检查 TLS 模式、端口及证书；认证失败时检查账号与授权码；邮件被拒绝时检查发件地址授权及收件地址。测试结果不会回显 SMTP 服务商的原始响应或密码。
