# 升级与回滚

升级是分阶段、只向前的切换。控制器会验证发布清单，拒绝数据库镜像变化，在旧版本继续服务时构建新服务，运行预检，创建并验证加密备份，执行迁移，最后通过就绪检查后启动新版本。

```bash
sudo scripts/deploy/metahubctl.sh upgrade /opt/metahub-state \
  /opt/metahub-releases/v2.1.0 v2.1.0
```

发布目录必须有与版本匹配的 `release-manifest.json` 和镜像锁定文件。旧版本、备份和 `recovery.json` 在业务验收结束前都要保留。迁移不自动降级；中断时使用新的状态目录执行 `recover`，不要删除 Docker 卷或手工修改数据库。

## SaaS 管理员升级中心

拥有 `platform_owner` 角色的 SaaS 管理员进入 **平台 → 基础设施**，可以查看正在运行的版本、宿主机升级服务已经验证的可用版本和历史任务。**备份并升级** 会把签名版本加入宿主机升级代理队列，不接受 shell 命令或任意路径。**重启服务** 只重启当前版本的 SaaS 服务，不切换版本、不修改数据库。两个操作都要求明确勾选确认，并会显示在任务列表中。执行期间 SaaS 控制台和组织网关可能短暂不可用；系统版本升级完成后，网关用户会自动使用新版本。

宿主机升级服务未启用时，页面会明确显示原因并隐藏操作。升级失败后会阻止继续操作，运维人员必须先检查备份和恢复状态；数据库迁移失败后不要用“重启服务”代替恢复流程。
