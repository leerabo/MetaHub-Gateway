# SaaS 平台管理员

SaaS 平台管理员是全新 MetaHub 安装时创建的首个账号。它负责平台级的组织、平台设置、供应商接入、发布运维和支持控制，和组织成员账号、应用调用用的 Virtual KEY 是不同层级的身份。

## 创建管理员

数据库迁移完成后执行一次：

```bash
sudo scripts/deploy/register-saas-admin.sh /opt/metahub-state
```

这个命令是底层安全流程的易发现入口，等价于：

```bash
sudo scripts/deploy/metahubctl.sh first-owner /opt/metahub-state
```

命令必须在交互式终端执行，会依次询问：

1. 管理员邮箱；
2. 显示名称；
3. 至少 8 个字符的密码，并再次确认。

它会在一个事务中创建首个平台注册账号、密码凭据、平台操作员、`platform_owner` 角色绑定、初始化完成记录和审计事件。密码和注册材料不会写入容器日志。安装阶段默认不强制 MFA，登录后可以在账号安全设置中手动开启。

## 生命周期规则

- 这是空数据库的一次性初始化；发现已有身份或业务数据时会拒绝执行。
- 它不是 HTTP 接口，不能通过浏览器请求触发。
- 它不会创建供应商 API KEY、组织成员、项目 KEY 或应用 KEY；登录平台后再配置这些内容。
- 若提示 `password_too_short`，请用至少 8 个字符重新执行。若提示 `database_not_empty` 或 `bootstrap_closed`，不要删除数据库，应使用已有账号和正常的账号找回流程。

## 登录后配置顺序

1. 登记供应商端点，并把供应商凭据保存在控制平面。
2. 创建对应用公开的模型别名和有序候选模型。
3. 选择固定顺序、可用性优先、成本优先或质量 + 成本路由。
4. 创建项目和应用，添加成员，签发有范围的 Virtual KEY。
5. 配置组织、项目、应用、人员或 KEY 预算，并发起一条小请求验证。

管理员账号只负责控制平面。客户端只能拿到范围受控的 Virtual KEY，不能拿管理员密码或上游供应商凭据。
