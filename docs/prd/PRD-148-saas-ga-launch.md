第二轮编码前自审：发布后复盘与申请回滚是独立操作，未提交复盘不得隐藏回滚入口。回滚待复核时只显示独立验证，回滚终态禁止重复申请。未形成 RC 候选或门禁目录为空时不得显示发布表单。原有 CSRF、step-up、幂等和 CAS 保持生效。

观察来源补充自审一：HEAD 不能唯一标识未提交工作树；采样开始和结束都必须记录源码内容摘要，传入的提交号必须等于实际 HEAD，发生内容变化不能给出同版通过结论。自审二：最终审计逐字段匹配两份快照和当前源码，拒绝缺失快照的旧观察；验证器的合成时间与真实短诊断仍不得替代连续 72 小时。

## 2026-09-12 PostgreSQL 复盘迁移补充自审

第一轮自审（权限与版本归属）：0163 的复盘角色授权需与 SQLite 0155 一致，初始化后的插入、更新、删除都拒绝。0162 与 0163 各自仅回滚其拥有的对象；验收必须通过统一迁移入口验证版本登记和重放，不直接执行 SQL 后假定版本历史正确。

第二轮自审（事实保护与恢复）：0163 down 应先恢复单发布唯一约束，再移除双字段索引与复盘授权表。已有同一发布的两种复盘结论时，唯一约束校验必须使整个事务失败，保留复盘、权限和 applied 版本；只有一条复盘时允许往返且内容完全相同。原生验收使用隔离集群的合成事实，不生成真实会签或发布证据。前端 MCP 生命周期回归需要执行实际注册的 hash/pagehide 回调，不能靠首个同名调用的文本位置推断执行顺序。

## 目标

为平台域提供从 `release_candidate` 到正式 GA 的可审计发布边界。GA 只能复用已签名的 RC 事实，不能通过前端或接口绕过证据、六方会签、发布后复核或回滚独立验证。

## 用户路径

平台管理员进入平台发布页后，只看到当前候选、20 个门禁的通过/阻塞状态和下一步。技术摘要、签名和内部操作人标识仅用于审计，不在普通工作区导航中展示。

1. 查看 GA 门禁。
2. 为已有 RC 门禁提交新鲜证据。
3. 六方会签及 RC 复核完成后执行 GA 发布。
4. 发生故障时由一名操作人发起回滚，另一名操作人验证回滚。

## 接口

- `GET /platform/ga-gates`
- `POST /platform/ga-gates/{ga_gate_id}/evidence`
- `POST /platform/ga-launches`
- `POST /platform/ga-launches/{ga_launch_id}/rollback`
- `POST /platform/ga-launches/{ga_launch_id}/review`

所有写操作要求平台会话、平台 CSRF、来源校验、幂等键、`If-Match` 和 step-up grant。工作区 Cookie、SupportSession、Authorization header 或混合凭据均拒绝。

## 发布条件

- 候选状态为 `release_candidate`。
- 20 个 GA 证据全部存在、通过且未过期。
- `long_stability` 至少 72 小时。
- product、sre、security、test、finance、legal 六方均已批准。
- RC 发布后复核已完成。

## 回滚与事件

回滚采用 request/verify 两阶段，并强制请求人与验证人不同。发布、批准和回滚事件进入事件表及 outbox，敏感原文不入库，仅保存摘要哈希。

### 部署事件 sink

部署可通过 `METAHUB_GA_EVENT_SINK_URL` 启用 GA 事件投递，并以独立的
`METAHUB_GA_EVENT_SINK_TOKEN`（可选）进行 Bearer 认证；连接超时由
`METAHUB_GA_EVENT_SINK_TIMEOUT_SECONDS` 控制（0.5–30 秒）。每次请求只发送
`event_id`、`event_type`、`payload_sha256` 和 `occurred_at` 四个字段，不包含租户、工作区、
会签人或事件正文。sink 返回非 2xx、超时或连接错误时，outbox 保持 `failed` 并按既有有界
指数退避重试；未配置 URL 时保持本地 durable outbox 行为，便于开发环境运行。

## 2026-09-11 增量设计与两轮编码前自审

计划依据：SaaS Excel `01_PRD总表` 第 60 行、`08_里程碑门禁` 第 10 行。仍需全域 QA、最终迁移对账、真实长稳和发布事实，接口注册或 RC 测试不能替代 GA 验收。

第一轮自审（权限、签名与请求所有权）：GA 执行必须复用 RC 的当前会签权限校验和执行人独立性校验。导入证据必须逐字段匹配已验证 RC 证据及签名摘要，不能忽略提交的时间、来源或指标。幂等摘要必须包含路径目标，避免在其他门禁或发布记录上重放既有结果。

第二轮自审（生命周期、回滚与证据）：72 小时判断使用签名证据的起止时间，不强制把通过率指标误作时长指标；同一事务内检查过期与撤权。无事实时允许 down，有证据、命令或事件时必须拒绝 down；SQLite RAISE 只能用于触发器。新增独立 GA 流程与迁移测试，明确测试时钟和模拟身份只证明实现，不构成真实审批或 72 小时运行证据。

## 2026-09-12 验收工具修正与两轮自审

当前产品 QA 审计仍固定在 139 条迁移、0139 版本、14,000 秒门槛，且使用旧间隔字段；它不能用于当前 GA 结论。当前 SQLite 基线为 153 条迁移、0155 版本。GA 长稳只接受 continuous-availability v1 的非诊断、已完成报告，真实观察至少 259,200 秒，逐窗口摘要链、计数和来源修订必须一致。四小时历史记录保留为诊断，不升级为 GA 事实。

第一轮自审（证据来源）：批次执行前后分别记录 Git HEAD 和受测源码内容摘要，源码变更使批次失效；测试输出按文件摘要绑定。摘要覆盖未提交的源码，避免把工作树运行结果冒认为纯 HEAD 结果。缺少来源、旧迁移和旧批次均不得计为当前版本通过。

第二轮自审（完整性与范围）：审计检查固定任务集合，拒绝重复任务凑数、缺失文件、截断窗口日志、诊断记录及短观察。审计工具只证明自动化测试和本地 HTTP 可用性；不代替六方真实会签、实际部署、回滚执行或跨环境终验。本批仅修改验收工具及其测试和文档，不重启正在运行的长稳进程，不回填旧证据的来源摘要。
