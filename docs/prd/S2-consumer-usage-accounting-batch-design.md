# 使用者用量与组织会话批次设计

日期：2026-09-09。状态：编码及本地发布完成，定向数据库/API/前端/布局验收通过；完整浏览器业务流程、规模性能与独立功能提交未完成。

## 依据与范围

只读核对原 Excel 的 `01_PRD总表`：PRD-094（第 6 行）要求逐请求 Workspace 授权及切换清理；PRD-099（第 11 行）要求用量可追踪、估算与应收分离、币种不隐式换算；PRD-144（第 56 行）要求平台商业账与企业内部成本账独立；PRD-147（第 59 行）要求存量页面真实可用及迁移事实保真。Excel 的已完成标记不代替运行证据。

本批交付组织会话下的用量概览、明细、创建导出、轮询、下载及免登录使用者归集。沿用 PRD-017/043 的账本、精度、快照水位和 CSV 合同，不新增平台收费事实。后续财务域及完整 PRD-148 门禁保持原范围，不由本批替代。

## 合同

- 使用现有 `require_workspace_or_legacy_permissions`，只接收一个 Workspace 或受支持的存量凭据。Platform、Support、员工 KEY 不得读取组织财务。
- 概览与明细要求 `billing.usage.read`。创建、状态与下载要求 `billing.usage.export`。创建和下载即使是 GET 也要求 Workspace Origin 与 CSRF。状态读取不再通过 GET 更新过期状态，清理由 worker 执行，DTO 实时投影过期。
- 服务层在自己的数据库事务中恢复会话、成员状态、租户、权限，查询与释放前复核。同步生成不长持写锁，创建/重放/审计提交前重新授权。
- 导出任务限定 tenant + requested_by，幂等键冲突不能使另一操作者取得原制品。租户外及非拥有者统一 404。审计失败与权限撤销不能留下任务或增加下载次数。
- `consumer_id` 是可选筛选，概览、明细、计数和 CSV 共用同一规范化函数。关联通过 tenant + KEY 查询不可变 `virtual_key_consumers`；不按姓名、部门、邮箱或当前 active 状态重分配历史。
- 概览增加 `by_consumer`，按稳定使用者 ID 聚合，未绑定流量单列。姓名和部门是当前目录标签，不声称为调用时部门快照。金额 CNY/USD 分列，估算数量单列。
- 明细增加 consumer_id。为保持 CSV 原列合同，CSV 仍按固定列输出，使用者筛选与稳定 ID 留在导出任务过滤条件，不扩展姓名/部门到文件和审计。
- 使用者归集默认只返回 ID 和计量字段，不把财务读权限扩展为员工目录读权限。额外满足现有目录权限（admin + user.manage + virtual_key.read）的主体可获得当前姓名/部门标签；读取与返回复核同一组权限。其他主体的标签必须为空。
- 前端复用 authenticatedResourceFetch、resourcePageLifecycle，切换组织、离页、撤权取消请求，迟到 CSV 不触发下载。不保存财务结果和 KEY 到 Storage。
- 无新增数据迁移；依赖 SQLite0148/PostgreSQL0155 的不可变关联。旧导出任务缺 consumer_id 时保持无筛选，原指纹规范不因空字段变化。

## 第一轮自审：权限与领域

1. 发现旧 `/usage` 路由只识别 Bearer，前端新组织会话没有 token。修正为整链适配，不能只改导航。
2. GET 导出创建任务，下载写审计。两者显式 CSRF，不能依据 HTTP GET 自动豁免。
3. 姓名和部门是额外人员信息。finance_admin 只取得稳定 ID；管理员额外满足完整现有目录权限时才取得标签，不通过财务读权限补权。
4. 平台订阅费用不等于 BYOK 成本。本批只读现有 Usage，不写订阅、支付、发票或应收。
5. 后端权限快照是唯一授权依据，不通过 owner/admin 字符串补权。

本轮 P0/P1 设计问题已通过以上合同处理，尚需测试证明实现。

## 第二轮自审：一致性与恢复

1. 同一租户的不同管理员可能碰撞 request_id。重放与状态/下载均绑定原 requested_by，返回一致 404，不交付其他人的制品。
2. 生成 CSV 后权限可能撤销。写事务开始及提交前复核，重放也必须复核，不能使用路由时的旧授权。
3. 改名、换部门、停用和 KEY 轮换不应改变历史归属。聚合只使用不可变绑定，不过滤当前 active。
4. 导出已有过滤 JSON 与指纹是历史合同。未指定 consumer_id 不添加空值到规范化结果，旧异步任务仍可运行。
5. 只给前端添加 cookie 不能处理迟到结果。查询、筛选、分页与导出都必须绑定组织及页面代次，导出重试仅在原 owner 内恢复。
6. PostgreSQL 的 GROUP BY 比 SQLite 严格。统一数据库验收需覆盖 Usage 各维度，不能从 SQLite 通过推断 PG 通过。

本轮 P0/P1 设计问题已通过以上合同处理，整批测试和原生 PostgreSQL 证据未产生前不得宣称完成。
