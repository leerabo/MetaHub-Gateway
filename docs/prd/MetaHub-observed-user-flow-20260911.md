# 用户可见接入流程复核

本轮以浏览器中的标题、说明和按钮为操作依据，使用独立的本地测试账号与组织。公开首页、注册、组织创建、模型服务选择、密钥保存和连接检查均在实际页面操作。

## 观察与设计

- 新账号只看到创建组织；创建组织仅填写组织名称。当前本地实测注册到可操作页面约 6.5 秒，创建组织到接入首页约 12.6 秒，耗时仍需单独定位。
- 厂家选择里出现英文默认名称和内部 vendor code。仅对官方目录默认名称提供常用中文名；保留自定义发布名称；把名称修改和自动生成的标识放在高级设置。
- 密钥保存后表单仍保持展开，像是在要求再次填密钥。保存后收起该表单，反馈直接指向测试连接；失败保留可重试入口。
- 真实 Kimi 测试返回 HTTP 401。当前页面显示内部服务编号和英文 failed，未说明下一步。改为中文结果与对应恢复动作；诊断状态码、耗时和后端安全摘要按需展开。不可把失败描述为可用。
- 旧浏览器旅程仍把 `/` 当控制台，并等待旧租户登录表单。改为新版账号登录后直接进入组织、退出后返回公开首页，保留原有认证、导航数据和权限断言。

## 第一轮自审：用户路径

厂家名称不要求用户理解供应商代码。名称、区域的自动选择仅在已有确定默认值时隐藏，多个区域仍需要用户选择。密钥保存后的下一步使用页面真实测试按钮，不标记模型已经可调用。员工身份与后台账号保持分离。

## 第二轮自审：边界与回归

改动只影响显示和表单展开状态，后端目录签名、实例化权限、模型服务凭据校验不变。密码输入提交后清空；失败不回填密钥。官方名称映射使用有限静态表，未知或自定义名称仍转义显示。浏览器测试不能用跳过断言或延长等待来代替修复真实入口。

## 按可见提示复走后的补充

- 已接入组织的管理员从接入步骤进入模型、路由、员工、接入信息。每页真实的模型服务缺口都仍可见；这属于配置和员工发放路径测试，不等同于模型成功调用。
- 实际为合成员工创建 KEY 后，表单仍展开并保留同一员工，会诱导重复提交。成功后清除创建选择，保留一次性结果，收起创建表单。
- KEY 名称已有可靠的员工姓名默认值，移至高级设置且允许留空；提交仍使用当前选择的默认名称。应用 KEY 保留独立命名与归属设置。
- 员工入口增加一句说明：添加档案再发放 KEY，员工无需注册或登录。添加完成提示直接指向创建 KEY。
- 一次性结果明确交付给员工的两项内容：KEY 和网关地址。模型入口由租户默认路由统一提供；Chat Completions、Responses 和 Anthropic Messages 共用同一凭据，工具按自身协议选择入口。对实际返回的 loopback 地址说明仅可本机试用，不伪造可供其他设备访问的公网地址。
- 连接中断恢复页移除旧登录卡片，以重新连接为主操作，错误详情按需展开，保持返回首页和重新登录入口。
- 隔离浏览器回归在首页 Three.js 初始化时报告错误。可选动画在创建渲染器前检查浏览器图形能力；无 WebGL 时保留静态示意和登录入口。没有放宽浏览器错误断言。

## 复验结果与保留问题

完整前端 2118 项通过；新增和相关定向回归 467 项通过；lint、隔离生产构建以及前后端发布摘要一致性检查通过。Chromium 管理员、开发者和只读角色三条实际浏览器旅程通过，包含 1280×720、1440×900、390×844，测得横向溢出与交互重叠均为零。详见同名测试记录。

真实浏览器手动复验确认：退出到新版首页；服务状态入口可达；账号设置没有先出现登录表单；刷新保持组织与当前位置；厂家选择显示常用中文名称；发放 KEY 仅需选择员工，完成后表单收起。

员工页面在第一轮出现一次 `TypeError: Failed to fetch`，页面重试后恢复。当前没有能确定该次请求根因的服务端关联证据，不能声明已消除偶发网络故障。历史注册约 6.5 秒、创建组织约 12.6 秒也仍是待优化项。真实 Kimi 401 没有被本轮界面修订解决，不能将管理员配置路径通过标记为真实模型调用通过。

## 2026-09-12 工具兼容性更正

本记录原先“Codex、Claude 选择 Chat Completions 兼容模式即可接入”的指引已废弃。当前 Codex 官方配置使用 Responses，Claude Code 使用 Anthropic Messages；网关已增加对应的受治理兼容入口。原浏览器旅程只验证了 MetaHub 的页面操作，不构成上述第三方工具全部 Agent 功能的真实验收。
