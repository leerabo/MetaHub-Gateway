# 商业服务请求执行边界批次

日期：2026-09-10。范围：PRD-098、099、102、103、104、105 的 HTTP 执行边界。
这是商业化完整交付的一项修复，不替代真实渠道、规模、浏览器和最终发布验收。

## 当前事实与实现合同

Excel 的商业模块已有实现，但多个 async 路由直接调用同步数据库服务。写锁、查询、
加密对象读写期间，同一进程的事件循环无法处理其他请求。PRD-099 的计量恢复已使用
工作线程，其他商业接口应沿用同一模式，而不是另建线程池或拆分事务。

- 只将完整的同步服务调用交给 Starlette `run_in_threadpool`，并等待结果。
- 请求流读取、严格正文解析、Cookie/CSRF/Origin 提取仍在原 HTTP 边界；同步 Depends
  保持框架原有工作线程执行。服务内数据库连接、授权复核、事务及关闭保持在同一次调用。
- 支付回调必须等待验签和 receipt 持久化完成才返回 202；不使用后台 fire-and-forget。
- 保留 DTO、状态码、ETag、幂等重放、错误码、no-store 和下载内容/文件名合同。
- 不迁移、不更改数据库或线上历史账务事实，不接触用户会话、KEY 或支付凭据。

## 第一轮自审：业务与权限

1. 线程转换不能扩大权限。组织财务、平台审核/财务/通讯和 provider 签名仍独立；
   服务收到原凭据后继续在事务内授权，不把依赖返回的旧身份当作最终事实。
2. 回调不能提前成功。完整同步服务被 await，验签、文件及数据库错误继续由原处理器映射。
3. 不按 SQL 分割事务。连接在服务中创建/关闭，不能跨线程传递已打开的连接或游标。
4. 账务与员工身份不变。组织 Owner 不获得平台权限，免登录使用者不新增登录账号。

## 第二轮自审：并发与验证

1. 覆盖每条同步服务分支，包括订阅切换/取消、CSV/PDF 下载和回调重放。
2. 独立心跳必须在模拟慢服务返回前推进；验证工作线程不同、ContextVar 传递及原异常透传。
3. 服务只调用一次，返回原 DTO；不能靠提高超时、吞异常或去掉鉴权消除失败。
4. 开发阶段只跑受影响边界单元测试，批次完成后统一运行商业 API/worker 回归和数据库检查。
   单元测试替换服务与解析辅助函数，不作为真实鉴权、数据库性能或外部支付通过的证据。

## PRD-103 并发回调补充设计与两轮自审

批次回归发现真正并发的 100 次已持久回调重放中 6 次 SQLITE_BUSY/503。旧路由阻塞
事件循环掩盖了同步串行化；不能回退成阻塞执行、提高 busy timeout 或降低并发数。

第一轮：验签和时间窗仍先执行。完整 schema 校验后，只读查询 provider/event 唯一收据，
只有正文 SHA256 恒定时间比较一致才返回已持久化事实。新事件或 hash 不一致仍进入
BEGIN IMMEDIATE 并重新查询，确保首次并发只有一个收据，冲突仍追加原有冲突状态。

第二轮：读取结果允许是当前状态快照，不修改处理租约、不重放商业效果。读路径不创建
对象、不提交事务、不绕过签名。验证持有其他写事务时相同回调仍可读，首次并发唯一性、
100 重放、同 ID 不同正文、乱序、退款/权益一次性和完整性。未变更金额、schema、超时或
历史线上收据；平台渠道真实接入仍不以模拟支付结果替代。

联合复测发现旧催缴测试冻结两个订单的创建时间后依赖随机 ID 的列表次序。
第一轮复核确认生产排序是 created_at DESC/order_id，第二轮将测试按目标 order_id
断言 past_due，同时断言旧订单仍 fulfilled；不修改排序、金额或状态机。
