# 试用入口、成员与模型接入修订

状态：已实施、通过桌面与手机真实浏览器验收并发布。范围为用户最新七项试用反馈，不包含 S3 未完成的后台修订。
验收记录：`docs/testing/MetaHub-trial-members-providers-20260910.md`。

## 交互与身份边界

- 登出成功回到新版首页；失效会话进入新版登录页，不再渲染控制台旧登录卡。
- 显式账号设置先显示账号页加载态，未验证会话不显示私有资料，也不短暂画登录表单。
- 邀请使用一次性 token 读取只读摘要，展示受邀邮箱、组织与职责；无效、过期或撤权邀请同形拒绝。
- 接受邀请仍由数据库恢复邮箱和角色。成功后用用户刚输入的凭据完成标准账号登录，再进入组织。
  登录失败不重放已经消费的邀请，提供新版登录入口。
- “后台成员”与“模型使用者”分开：模型使用者不需要账号、密码或注册，只关联部门和独立 KEY。
- 订阅和成本页使用已经验证的 Workspace 会话及权限摘要，不伪造旧 tenant/user/session 字段。
  身份缺项展示明确错误，可重试，不永久停留“待加载”。
- Provider 默认显示已配置列表；添加时选择目录厂家，仅展开当前配置。自定义接入和各密钥池折叠。

## 第一轮自审

- 不能在邀请预览接受客户端邮箱或角色；只按 token 哈希查询，响应不缓存、不记录 token。
- 不能接受邀请后继续沿用管理员的旧会话；必须使用受邀用户自己的标准登录结果。
- 不能用兼容旧字段来放松身份隔离；商业账务 owner 显式绑定 GlobalSession 和 Workspace 授权版本。
- 登出失败不能宣称服务端已经退出；错误态与成功跳转分开。

## 第二轮自审

- 邀请消费与后续登录是两个阶段；登录失败保留“已加入”事实，避免诱导用户重复消费。
- 切换厂家、关闭配置和离页必须清除敏感输入，旧响应仍受现有 owner/generation 管理。
- 新建使用者不能给员工扩大后台访问权限；邀请成员不替代使用者管理。
- 发布仅纳入本轮已验证 UI/API 改动，排除未完成的 S3 runtime/capacity 文件。
- 用真实浏览器覆盖登出、账号设置、邀请摘要/接受/登录、免注册使用者、订阅和 Provider 选择。
