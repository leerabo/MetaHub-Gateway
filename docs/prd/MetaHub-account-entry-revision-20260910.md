# 登录入口与账号设置分区修订

范围：试用反馈中的登录落点、账号偏好空状态、综合账号页表单堆叠和初始化入口。
保留 PRD-092/094/097/116 等既有 API、鉴权、幂等及敏感值清理合同，不修改数据库。

## 交互合同

- 普通登录或恢复登录后，已有可信 WorkspaceSession 则进入空间控制台。只有一个组织时沿用
  现有显式切换后校验机制；多个组织且无当前空间时先选择。无组织仍只提供创建组织主流程。
- 邀请、账号恢复及明确打开账号设置的请求不自动跳转。所有跳转目的地固定为本地控制台，
  不接受用户提供的任意 return URL。控制台独立复核会话和权限后再显示私有数据。
- 账号页一次只渲染一个栏目。组织空间、账号安全、登录设备、修改密码和语言设置独立展示；
  组织管理栏目放在次级导航内，按已有权限裁剪，保留原功能，不让新账号填写企业高级配置。
- 仅读取当前栏目的业务数据，语言设置在直接登录、页面恢复和主动进入三条路径都可加载。
  栏目切换取消旧读取、清理一次性密钥和密码，迟到响应不能恢复旧页面。
- 初始化每一步都保留受控配置链接，包括需要确认的空间资料和环境步骤。链接进入真实
  控制台功能，确认仍执行原后端校验和 CAS，不将配置链接当作完成事实。
- 旧的账号偏好和邀请成员锚点映射到新栏目。站内导航及浏览器前进后退恢复同一栏目。

## 第一轮自审

普通登录走旧综合页、只有组织创建走控制台是落点不一致的原因。不能只隐藏长表单，
必须改变渲染和读取范围，同时保留高级功能的可达入口。账号设置链接必须明确目标，
否则自动进空间会使账号页无法访问。无组织、多个组织、邀请和 recovery 会话单独验证。

## 第二轮自审

切页时请求代次必须失效，恢复码、SCIM bearer 和机器凭据不得驻留跨栏目 DOM。
Workspace owner 必须匹配账号目录，authorization 必须完整，自动跳转不能绕过控制台
的独立鉴权。首次登录的偏好读取不得依赖仅 mount 会执行的分支。新 UI 不需要 schema
或用户数据操作；测试使用隔离数据，发布保留现有账号、组织、KEY 和账务。

真实浏览器追加核对：GlobalAccountSummary 有意不公开 account_id，旧偏好 owner 依赖
该不存在字段而不发送请求。内存 owner 使用已验证的 GlobalSession ID，该 ID 跨账号唯一，
会话轮换后旧请求必然失效。不向公开 DTO 添加内部账号 ID，不把邮箱写入新存储。

偏好接口的浏览器 Cookie 合同追加自审：同源浏览器同时携带 GlobalSession 和 WorkspaceSession，
旧偏好路由错误地拒绝两者共存。沿用现有导航偏好路由的合同，仅忽略 Workspace Cookie，
仍只使用唯一且有效的 GlobalSession 授权；写入必须匹配 Global CSRF 和允许的 Origin。
Platform/Support Cookie、Authorization、缺失/重复 GlobalSession 和跨域写入继续拒绝。
第二轮复核服务仍从 GlobalSession 恢复账号，没有任何 Workspace Cookie 到账号授权的回退。

## 验证计划

针对性状态机与渲染测试先行；随后统一执行受影响前端回归和生产浏览器流程。
覆盖已有组织重新登录、无组织、组织选择、账号栏目、偏好加载/重试、资料入口、
历史导航、恢复/失效/迟到响应和 1280/390 视口。不重复本轮未修改的主页动画全量测试。
