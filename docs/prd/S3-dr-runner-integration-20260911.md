# S3 真实容灾执行接入

日期：2026-09-11。范围：PRD-106/111 共享持久调度、独立恢复服务和绑定证明。
状态：两轮编码前自审完成，实施中。Excel 01_PRD总表第 18、23、25 行及 G3 门禁保持完整。

## 端到端设计

1. 控制面从已经双人批准的 run/recovery/job 绑定生成 RestoreRequest，固定执行 ID、根任务
   generation、备份身份、对象键及内容/manifest/水位/schema。部署目标、区域、环境和执行
   总截止时间一起进入不可变派发摘要。任务提交内容不能指定连接串或凭据。
2. 控制面在短事务中持久保存执行绑定并 defer_external，之后通过独立恢复服务的内部接口
   提交、观察或取消。每次交换使用独立服务 token 和有域隔离的短期 HMAC 许可；许可绑定
   动作和完整派发身份，观察续期不改变执行总截止时间。非本机链路必须使用 HTTPS。
3. 恢复服务按单一部署目标运行，私有设置文件固定区域/环境、备份运行配置与目标管理入口。
   入口不读取仓库 .env，不接受请求选择文件/URL。敏感设置引用部署方的绝对私有文件路径。
   身份与目标作用域的摘要先写私有不可变登记，再使用已实现的 RestoreExecutor.register。
4. 使用有界后台执行和每 execution 文件锁；HTTP 请求不长时间执行 pg_restore。控制面
   continuation 是可重放派发的持久来源。服务重启后，status 只对已登记执行恢复观察/派发：
   started=0 可首次执行，started=1 只能确认停止并中断。status 不得为丢失的日志创造新执行。
5. 取消可以先于 submit，落不可撤回的登记。启动前取消无需连接目标；已经启动的取消必须
   经现有文件/数据库停止确认。目标或结果不一致、观测失败、超时不能伪装成已停止。
6. 控制面核对 response 执行 ID、完整派发摘要、request 摘要和真实 RestoreResult。使用
   ExternalJobContext.commit_effect 原子提交恢复结果与阶段事实，继续同一根 attempt。
   中间成功不调用 finish。只有全部真实依赖验证完成才结束根任务。
7. 新增控制面恢复执行与证明事实，使用 SQLite/PostgreSQL expand 迁移及不可变约束；旧 run
   不回填猜测证明，down 遇到事实拒绝。只在隔离验收库升级，不迁移当前试用 schema 0150。
8. 移除当前 metadata-only validate_restore 和按编号生成 verify 摘要的成功路径。真实快照
   指纹只证明对应数据一致，不能投影成对象跨区副本、KMS 区域恢复、业务账本守恒、生产
   writer fencing 或 Gateway ACK。缺任何必需组件都不得实际切换或报告 dr.objectives_met。
   这些依赖仍属于 PRD-111 本批范围，须继续实现并分别提供真实证据，不据此缩小验收范围。

## 第一轮自审：边界与信任

- 恢复服务是受部署控制的独立服务，不是企业空间 API，不共享容量运行器的命令域或密钥。
- 复用现有 RestoreRequest/RestoreResult 和短事务 effect 协议；不复制数据库恢复逻辑。
- 许可先检查签名、时效、动作和部署 scope；错误响应固定化，禁止返回校验输入、许可原文、
  连接串、子进程输出或客户行值。HTTP 输入/队列/结果有大小边界，响应 no-store。
- 相同执行 ID 的区域/环境/目标/截止时间变更必须拒绝，不能仅依靠 request 内的备份摘要。
- 服务终态必须来自私有 journal 的匹配结果；缺失 journal 不是可以重新发起恢复的依据。
- 可恢复数据库仍为隔离产物。恢复服务没有 DROP、覆盖或自动提升生产库的权限。

## 第二轮自审：故障与接管

- 控制面入队/绑定提交后断电、首次提交响应丢失、服务登记后派发前断电，都由同一持久
  continuation 重新驱动；没有“HTTP 已返回”等同于业务成功的状态推断。
- 后台开始前复核许可时效和总截止时间；过期的暂存许可不启动新效果，新的合法观察可继续
  已登记且尚未启动的工作，但不能延长原始执行截止时间。
- 观察租约失效后旧控制面不能提交证明；已提交阶段重复观察幂等，不重复恢复或业务写入。
- 停止确认之前保留等待。关停服务先停止接受派发并请求现有执行停止，线程回收后才退出。
- 测试按当前实施模块先跑协议/服务/状态机专项，再做真正 HTTP 和原生 PostgreSQL 恢复链；
  控制面接入后统一覆盖双数据库迁移、进程重启、取消、权限、目标错绑与未满足证据门禁。
- 服务与控制面都不使用合成成功结果代替实际恢复。G3 的跨区依赖、RPO/RTO、容量长稳等
  必需证据仍未完成，不允许把部分测试通过写成整个 S3 完成。
