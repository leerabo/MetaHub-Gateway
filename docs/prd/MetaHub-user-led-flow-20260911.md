# MetaHub 用户可见路径修订

## 观察范围

接续已有真人试用记录，先走登录、组织首页、模型服务、模型、路由、员工 KEY、接入信息。
再按“接入已有兼容网关”的用户目标从首页开始，只根据可见入口操作。使用既有合成验收组织，
不修改用户组织，不迁移数据库，不调用付费模型；不把读代码后找到的入口计为自然路径通过。

## 本轮问题

- U39：自定义服务仍要求填写 Code，协议与认证枚举抢占主要字段，提交后不衔接密钥配置。
- U40：每个模型服务有两处相同的配置 API KEY 入口；密钥读取失败可能藏在折叠区内。
- U41：模型与路由页面的下一步未承接组织的真实接入缺口，最后“验证首次调用”只显示连接资料。
- U42：路由依赖环境为空或加载中时，禁用原因藏在高级设置；不能让用户猜灰色按钮的原因。

## 修订与第一遍自审

自定义服务主要字段保留名称、地址；内部标识自动生成，协议、认证、备注按需展开。
创建成功后只展开刚创建服务的密钥区。自动生成标识在失败重试期间保持稳定。
服务列表保留一个密钥入口，展开与关闭就在原地完成；加载失败在折叠区外提供重试。
模型、路由和接入页复用组织首页的服务端任务事实，显示当前缺口和真实操作入口。
首次成功调用由服务端事实确认，刷新状态不产生模型调用，不增加假的“完成”按钮。
环境缺失、加载中和失败分开显示；只有一个环境仍可使用默认值，不要求用户理解内部 ID。

## 第二遍自审

状态复用现有 workspace navigation owner、权限快照和取消机制，不新增数据库或授权规则。
跨组织、退出、角色变化后的旧响应不能写回当前页面；401/403/冲突仍走现有身份边界。
普通依赖失败不能清空已加载的连接资料；未知或过期状态不得显示接入成功。
操作入口仅采用服务端允许且在本地登记的固定路由；同页缺口不生成自我跳转循环。
折叠不是安全边界，后端仍校验写入；关闭密钥表单继续清除未提交的明文。
不自动创建员工账号、授权凭据、订阅或付费调用，不把 UI 状态等同于完整系统验收。

## 验收

补充渲染、事件、身份过期与依赖失败回归；生产构建后重新沿可见入口操作，检查桌面和手机。
保留原生产静态文件供恢复，不带入未完成的 S3 恢复开发代码。
