# 订阅历史归属与平台计量恢复批次

日期：2026-09-09。PRD-098/099/147 联合增量，附 PRD-100 数据库异常兼容修复。状态：已实现并完成隔离验证；运行发布与真实平台 MFA 会话验收仍待完成。

## 权威问题与目标

运行库有两条未投影用量。首条 Token 一致、唯一组织绑定，但发生时间没有权益快照；outbox 已 failed/owner_invalid，严格连续检查点阻塞下一条。没有历史合同不能补造权益、套用当前价格、自动视为免费或直接跳过序号。

平台财务需要看到当前阻塞事实、历史权益可用性及操作结果，在确认依据后选择重新投影或归档为仅内部成本。企业 Owner 不是平台管理员，企业空间不提供该恢复能力。内部 Usage/FinOps 与平台商业账仍独立。

## 批量实现合同

- 新增平台专用 `GET /platform/billing/metering-state` 和 `POST /platform/billing/meter-recoveries`。读取要求 platform.billing.read，操作要求 platform.billing.adjust 与现有平台 MFA 会话、Origin、CSRF；拒绝 Workspace、Support、Bearer 或混合凭据。
- 只处理当前 checkpoint+1 的 failed outbox。提交携带 outbox ID、source sequence、attempt count、服务器生成的事实 SHA256 与幂等键；正文不得包含 tenant、workspace、历史价格、金额、权益或原始请求内容。
- `retry` 恢复该 outbox 为 pending，保留尝试次数；不推进检查点、不同步重写历史合同，worker 继续原有投影事务。若根因仍在，界面仍显示真实失败。
- `internal_cost_only` 仅允许 owner_invalid、数量有效、唯一组织绑定、无已生成 MeterReading，且用量时间早于任何已有订阅创建时间并无对应历史权益。已在订阅期但权益缺口、坏数量、未知归属、未知 meter 不允许此操作。
- 归档是明确的非平台计费分类，不是“零费用”。追加不可变恢复事实和平台审计后，在同一事务严格将检查点从 sequence-1 推进到 sequence；保留原 outbox 失败证据、Usage 和内部账本，不创建 cycle/allocation/reading/summary 或金额。
- 新增 SQLite 0149 / PostgreSQL 0156 `platform_meter_recovery_actions`，绑定原始 usage、outbox、序号、tenant/workspace、平台操作者、动作、原尝试次数、事实/正文/幂等摘要和 request/trace。每次失败尝试只允许一次恢复，同操作者同幂等键只能有同正文重放。
- 数据库约束验证源事实、组织与当前检查点归属，动作事实禁止更新删除；登记租户数据保留目录。pristine down/up 可用，有恢复事实后拒绝回滚；不改已应用迁移、不删除源事实。
- 服务自持事务；读在返回前退出旧快照并重新授权，写/重放在返回或提交前复核当前平台权限与会话。数据库故障、审计失败、CAS 失败整体回滚，不留下已归档但未推进或已推进但无证据。
- 前端在 SaaS 平台账单页增设平铺的计量状态区域，显示待处理计数、组织、发生时间、阻塞原因和处理记录。命令需要明确确认，归档不可默认选中；异步响应和恢复意图遵循平台页面代次，离页/退出/身份变化清除旧目标。
- 旧订阅/计量 API DTO 不增加字段，以免破坏既有严格客户端。新接口严格字段及 no-store，响应与审计不含姓名、邮箱、KEY、Prompt/Response 或供应商端点。

## 第一轮自审：账务与归属

1. 缺少权益不等于零应收。区分重试与仅内部成本的明确决定；既有订阅期内的权益缺口禁止归档，避免免除已有合同费用。
2. 自动跳过坏行会漏计费。仅平台受权操作者可为当前连续序号追加归档事实，原始 outbox 错误保留，后续检查点仍严格 +1。
3. 一个动作不同时改内部账和商业账。归档不创建平台金额、权益或 MeterReading，内部费用仍可按 KEY 追溯。
4. 仅校验 tenant 不足。恢复事实由源 Usage、outbox、序号和唯一 Workspace binding 共同恢复；客户端不能指定 owner。

## 第二轮自审：并发、权限与回滚

1. 两个操作员同时归档不得推进两次。当前头部检查、原尝试唯一约束与 checkpoint CAS 同事务，竞争失败整体回滚。
2. 重试后旧窗口不能归档新的失败尝试。attempt count 与源证据摘要绑定目标；同正文重放只返回原恢复结果，不二次追加或执行。
3. 读权限撤销、会话撤销、审计失败和数据库错误必须保持无写入。工作线程执行同步数据库服务，按既有 PlatformSession 逐次复核。
4. 生产事实是否归档由明确业务决定，不由测试证明替代。开发验证使用隔离数据库；运行库继续只读，收到用户对这两条旧测试用量的答复后才考虑实际归档。

## 验证安排

连续完成迁移、DTO、服务、API 和前端后，先受影响单元/API；整批统一双数据库、同源并发、重放、审计/撤权故障、旧计量回归、真实浏览器与短性能。每个 PRD 保留独立测试/敏感审计/提交。此批不取消 Excel 的其余支付、身份、迁移治理与 72 小时门禁。

## 实现后复核与证据

- 恢复读写在进入 try/finally 前拒绝调用方已有事务，避免错误清理撤销别人未提交的操作。confirmed 只接受实际布尔 true。
- SQLite/PostgreSQL trigger 同时检查失败头、原尝试次数、源序号、唯一组织、数量和订阅历史；已有订阅期的缺口不能归档。PostgreSQL 归档事务持有合同表 SHARE 锁，阻止检查至提交间插入合同证据。
- SQLite 时间比较采用 julianday；毫秒以下临界值采用保守拒绝，不能因此把本应计费的事实归档。跨引擎精确微秒等价不作为已验证结论。
- 全局最近记录增加 created_at/recovery_id 索引。前端恢复目标、动作、幂等意图按页面生命周期清除，迟到的会话结果也不能覆盖新操作者。
- 后端最终 17 项通过（包含原计量关账/迟到用量/调整回归），前端 22 项通过，共享数据库 59 项通过，原生 PostgreSQL 1 个复合迁移/并发流程通过。证据详见独立记录。
- 20 次服务读取沿用真实 GET 的 request-owned warm connection，p95 39.751 ms；这不是含真实认证、网络和大规模历史事实的 HTTP p95。未复用连接的冷开 schema 测试曾测得 732.594 ms，原结果保留。
- 浏览器桌面 1280px、移动 390px iframe 视口真实渲染无页面溢出或表单剪裁，标签 14px，默认动作空且确认框未勾选。使用 synthetic DTO，不是 authenticated browser E2E。
- 运行库未迁移，旧失败事实未改写，前端 dist/运行进程未替换。下一步是实际平台会话闭环、发布验证与继续 Excel 的其余门禁，不把此增量视为总目标完成。
