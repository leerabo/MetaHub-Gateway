# S3 外部执行等待与取消

范围：PRD-106 持久运行时与 PRD-113 容量执行衔接。原计划只读核对
`01_PRD总表!A18:Y25`，不修改 Excel 完成状态，不更新当前试用服务。

## 设计

保留原 job、attempt、generation 和领域 job_id。新增外部等待事实及短时恢复租约，
不修改普通失败重试的 20 次限制，不用后继任务冒充根任务成功。
原 handler 在持有有效租约的事务里完成领域 start、加密续接参数和等待记录，
同时释放普通租约。该事务之前和事务内均不发外部请求。
后续恢复租约有独立递增 generation、随机令牌 HMAC、数据库时钟与外层调度 fence。
每次恢复只做一次有界交换。等待不占普通执行槽，恢复交换受队列并发限制。

原任务保持 running，取消后保持 cancel_requested。只有受 fencing 保护的恢复者，
在执行器确认终态后，才能原子提交领域事实、幂等效果、原 attempt、原 job 和 outbox。
外部操作截止时间独立于短时领取期限。超过截止时间只能发停止请求，不能直接终结。
网络/KMS/协议失败保留等待及固定公开原因码，并退避重试。停服丢失的恢复租约可接管，
不得把 pending、恢复次数或依赖故障计入普通失败重试。

平台详情只公开等待状态、计数、时间及固定原因码，不返回续接内容、令牌、签名或工作进程身份。
续接参数保持不可变，加密并绑定 job/type；后续确认提交的状态只能从 false 变为 true。
SQL 禁止存在未完成外部等待的原任务被普通路径终结或重新排队。
等待和恢复租约都是保留事实，down 在有事实时拒绝删除。

## 第一轮编码前自审

- P0：提交成功、响应丢失时，不能新建压力任务。领域对象及 execution digest 固定，重复提交幂等。
- P0：登记与领域 start 必须同一事务，否则崩溃会遗留没有恢复所有者的压力执行。
- P0：取消早于提交时必须发送幂等 cancel，执行器持久 tombstone 阻止迟到 submit。
- P0：停止未确认不得把原 job 标为 cancelled/failed，即使超过执行截止时间。
- P1：不开放任意外部 handler/URL；恢复逻辑只允许编译期注册，原始异常不得进入审计。
- P1：原 job/attempt 不重新分配，普通重试不应把外部终态复活；已有外部事实拒绝手动 retry。

## 第二轮编码前自审

- P0：旧恢复者网络返回较晚时，必须再次核验租约、恢复代次及外层 fence，再提交领域结果。
- P0：取消与结果落库竞争由原 job 行锁串行化，取消优先，不生成健康基线。
- P1：普通 heartbeat 在交接后只能失去租约，不得终结已交接任务。
- P1：队列暂停仍应允许已有执行的观察和停止；新增执行仍服从任务类型启停。
- P1：旧 worker 不认识等待记录。已交接任务释放普通租约后不可被旧 worker 领取；
  SQL 增加终态保护。升级前必须暂停 capacity 类型并排空旧 worker，未验证混跑不得发布。
- P1：测试覆盖超过 20 次 pending、跨 24 小时等待、崩溃接管、过期所有者、取消竞争、
  依赖故障、事务回滚、外层 fence 和无敏感 DTO。压力仅使用隔离目标。
