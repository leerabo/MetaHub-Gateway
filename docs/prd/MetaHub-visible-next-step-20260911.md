# MetaHub 可见下一步修订

日期：2026-09-11。

## 用户路径与问题

沿公开首页、登录、空间首页的步骤按钮、员工与 KEY、接入信息实际点击。
仅使用既有合成验收账号和“体验验收组织 0910”，未通过内部路由代替发现入口。

- U47：任务和返回链接切页后，侧栏仍展开原分组；当前位置可能折叠或在滚动区域之外。
- U48：新会话清理旧内容后，业务读取期间画面为空，没有等待反馈和返回入口。
- U49：员工页已有 KEY 就推荐接入下一步，却不检查模型服务和路由，下一页又要求返回。
- U50：补配置与普通关联链接只改变地址，读取期间保留原内容，缺少即时切页反馈。

## 设计

导航切换时展开后端已授权目标所属分组，仅滚动侧栏使当前项可见。
同页数据更新保留用户正在查看的导航分组和滚动位置。
身份和资源重新绑定仍先清除旧私有内容，再显示无敏感信息的加载与返回首页入口。
员工页复用既有接入事实及恢复动作；服务、模型、KEY 都完成后才强调接入下一步。
事实缺失、过期或失败时保留资料入口，不暗示已可使用，不妨碍管理员预先登记员工。
补配置与关联入口复用同一授权导航流程，立即显示目标栏目与加载态，保留浏览器修饰键行为。

## 编码前检查

1. 可用性：不增加必填项、不增加说明面板、不把隐藏菜单当作已发现的入口；步骤提示保持一致。
2. 边界：不改变权限、会话隔离和一次性凭据处理；后台刷新不抢焦点；新增状态读取沿用取消与失败规则。
