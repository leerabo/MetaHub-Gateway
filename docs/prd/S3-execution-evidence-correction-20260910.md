## 执行基础修订

106 不引入任意代码或新的 owner 表。每次领取按数据库时间确定 attempt 时限，来源为不可变类型目录
`timeout_seconds`，从 attempt 的 `leased_at` 起算，覆盖解密和前置准备。续租不得超过该时限。
checkpoint、数据库效果和最终成功均复验时限、租约、generation、外层 scheduler fence。
心跳使用独立线程和独立数据库连接，取消时完成取消终态，超时时停止续租并记录固定失败码。
数据库失败和过期不能通过心跳复活。handler 返回后停止并回收心跳线程。

Python 无法安全强杀任意进程内 handler：本修订保证超时后数据库提交权限失效，不声称停止了所有外部副作用。
长时外部执行必须使用可停止的隔离进程或持久异步 runner，并在外部提交处实现独立 fencing。
不能为卡死 handler 无限续租，也不能用 detached handler 线程假装完成了有界停服。

113 先移除 HTTP 路径的模拟成功。保留仅 `environment=test` 且显式 `test_loopback` 的单元测试模拟器。
真实执行尚未接通的 HTTP 接口返回固定不可用码，目录校验、认证和 kill fencing 保留。
这是防止错误验收的修正，不是实际压测功能交付。

结果协议版本升级：明确 `evidence_kind`，绑定 operation、object、manifest 和稳定执行参数摘要。
参数摘要排除短期 permit 的签发/到期时间，以支持同一任务在重启后重新签发；保留 kill generation。
结果摘要包含版本、来源、参数绑定、全部聚合字段和 outcome，排除摘要字段本身和空值。
Control 拒绝缺少新字段、摘要不符、跨对象/场景/环境、乱序百分位、模拟 HTTP 结果与未知 outcome。
HTTP 请求禁用环境代理和重定向，不将内部 Bearer 或 permit 交给环境代理。

## 后续真实执行合同

真实 runner 使用固定签名场景和独立合成租户/KEY，只对部署侧 allowlist 的隔离服务施加负载。
持久 submit/poll/cancel，按 object/manifest/参数摘要幂等；Control 超时、重启不能重复施压。
采集实际请求计数、延迟分位数、吞吐、错误、资源曲线和租户公平性，不以目标 RPS 推导实测值。
故障适配器必须证明注入与撤销，连续检查停止条件；无适配器、遥测或恢复证明就不能成功。
恢复证据需读取恢复后的账本、outbox、配置 head 和真实 schema 水位；标识摘要不是恢复证明。

## 第一轮自审：真实性与授权

- P0：模拟成功进入生产基线。HTTP 禁止模拟，版本化结果来源必须由 Control 校验。
- P0：仅 checksum 不能证明真实测量。checksum 只做完整性；实际测量、停止和恢复另有验收责任。
- P1：只绑定 object 仍允许不同环境/负载重放。增加稳定完整参数摘要，并保留 kill generation。
- P1：心跳可能绕过旧 generation/外层 fence。统一调用现有数据库围栏，不使用内存布尔值授权提交。
- P1：修改已有试用或历史证据会混淆交付。仅新增修订记录，不覆盖历史基线或修改在线数据。

## 第二轮自审：竞态与资源

- P1：到期后续租会复活任务。先检查到期与取消，数据库时限限制所有续租。
- P1：心跳与 handler 共用连接会跨线程干扰事务。心跳拥有独立连接，正常结束显式 join。
- P1：取消期间无限续租会阻止收敛。心跳提交取消终态；迟到结果不能提交业务效果。
- P1：不合作的 Python handler 无法强杀。保留这一限制，外部任务转隔离执行是后续必做项。
- P1：旧 runner 混合部署不支持新合同。旧格式必须拒绝，Control/runner 同批升级，不向旧格式降级。
- P1：大数据库复制挤占试用磁盘。基础测试优先使用独立小型 schema 和真实迁移约束，不复制在线库。
