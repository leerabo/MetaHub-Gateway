# S3 持久恢复执行生命周期

日期：2026-09-10。更新：2026-09-11。状态：执行器实施单元已验证，DR 接入待继续。
承接 `S3-dr-bound-execution-20260910.md`，保留 PRD-106..113 整批范围。
Excel `01_PRD总表` 第 18、23、25 行分别要求持久任务接管、实际恢复一致性和依赖故障门禁。

## 共享设计

1. 独立恢复执行器使用部署指定的私有状态目录，先落执行身份、请求摘要、后端与目标摘要，
   再产生外部效果。请求绑定 run、job/generation、backup、manifest、内容、schema 和源水位。
   同执行 ID 不得替换请求或配置目标。日志和 journal 不存连接串、密钥、客户行值。
2. 每个 execution ID 分配一个新 SQLite 文件或 PostgreSQL 数据库。PostgreSQL 管理入口由部署
   指定，不接受任务提交连接串。仅操作固定命名空间、确定名称和匹配所有权标记的目标，
   禁止 `--clean`、DROP 或覆盖原有数据库。
3. 文件锁排除同 journal 并发，PostgreSQL 管理连接持有目标级 advisory lock，覆盖创建、
   恢复、验证和停止。新库初始禁止连接，写所有权标记后才开放；遇到已存在但未标记的库拒绝操作。
4. 恢复使用已有加密 manifest 和实际数据库指纹。新增协作停止检查、可停止 pg_restore 子进程、
   SQLite progress handler 和逐页指纹检查。错误不透出子进程 stderr。
5. 取消、异常和重新接管必须先封闭目标准入、终止该目标会话并读回零活动会话，才报告已停止。
   无法证明停止时保留 stop_pending，之后重试同一执行进行确认，不因观察超时换目标重跑。
   正常完成也封闭隔离目标，保留真实恢复产物和摘要。恢复目标不是已提升的生产数据库。
6. 崩溃后无持久成功结果的执行，只能确认停止并记 interrupted；不猜测成功、不覆盖残留产物。
   完整重试由新的执行 ID 承担。持久成功重读不再恢复，且请求/目标必须相同。
7. PRD-106 后续持久外部等待以此执行结果继续 DR 阶段；需要事务内续接，不能用 finish 提前
   完成根任务。当前实施单元提供真实执行与接管基础，不声称路由 ACK、账本守恒、KMS 跨区、
   RPO/RTO 或整个容灾流程已完成。接下来移除 metadata-only 成功路径并连接实际证明。

## 第一轮自审：身份与破坏范围

- 仅 URL 不同不足以隔离目标，沿用 manifest 中的实际源数据库身份核验；v1 无完整指纹，
  持久恢复不得把它升级成 v2 成功证明。
- PostgreSQL CREATE DATABASE 与 COMMENT 不是同一事务。先禁用连接，即使在写标记前崩溃，
  也没有恢复子进程进入；未知标记保持拒绝，不为可用性去猜测其归属。
- 停止 SQL 必须限定已确认的目标 OID，不终止管理库、源库或别的执行。重新读取 OID/标记，
  防止同名不同库被误操作。执行器不主动删除失败证据或数据库。
- 私有 journal 只存有界字段与摘要。凭据仅在内存和子进程必要环境中，异常只保留固定安全码。

## 第二轮自审：崩溃、取消与证据

- pg_restore 父进程退出不证明 PostgreSQL backend 已停；重新接管必须在服务器确认目标已封闭
  且无会话。观察失败不是停止，stop_pending 不可投影为 cancelled/failed/verified。
- 进程句柄必须被 wait/reap；取消检查失败也先停止子进程。子进程不能继承 journal 锁。
- 成功验证后、journal 提交前崩溃只能记 interrupted；已落库成功可幂等读取，但不能变更绑定。
- SQLite 使用独占创建，不能覆盖任何已有路径；持有跨进程文件锁直至读连接关闭。
- 新增真实 SQLite 和原生 PostgreSQL 专项：独立目标、取消、重启残留会话清退、并发排斥、
  非所属目标拒绝、数据一致性和敏感审计。不重复 S3 全套，不重启或迁移 5173/8001 试用栈。

## 实施核对

- 新增私有 journal、执行文件锁、每执行独立恢复目标和 PostgreSQL 所有权/OID/服务器绑定。
- 成功必须同时具备匹配证明与停止确认；失败/取消/中断不得携带成功证明。
  读取、重放及取消均复核持久结果与 journal/request 的绑定，损坏结果返回固定安全码。
- 子进程停止确认独立于异常消息保留，后续清理异常不得掩盖未确认停止。
- 原生取消测试使用恢复前创建的有效 CHECK，且只在新建恢复库中延迟 COPY；真实观察到
  PgSleep 后取消，验证进程已回收、库准入关闭、后台连接为零。
- 84 项恢复/备份测试均有通过证据，详情及一次环境依赖失败的处置见
  `docs/testing/PRD-111-durable-restore-20260911.md`。完整 S3 和 PRD-111 未完成。
