# S3 恢复登记与派发顺序

日期：2026-09-11。范围：PRD-111 私有执行日志，为 PRD-106 持久外部派发提供前置条件。
状态：两轮编码前自审及实现验证完成。依赖已提交的真实恢复执行器和外部阶段续接。

## 设计

1. 增加 `register`，只持久登记不可变请求/目标摘要，不连接恢复数据库、不读取备份、不派生
   外部效果。控制面的加密 continuation 保留请求，丢失派发响应时以同一身份重复登记/执行。
2. 日志区分“已登记、尚未启动”和“已开始外部执行”。新增 started 单调标记，持有执行文件锁
   的 worker 在同一日志事务中确认绑定、取消标记并把 started 从 0 改为 1，然后才做恢复。
   登记后进程崩溃可继续首次执行；已经 started 的崩溃仍只确认停止，不覆盖产物重放。
3. 登记可同时持久写入 cancel_requested，支持取消请求先于迟到的派发请求。迟到 worker
   只能落 cancelled，不连接目标或创建数据库；已经启动的恢复仍按原有停止确认流程处理。
4. 私有旧 journal 在事务内新增 started，已有记录保守默认 1。不能猜测旧 running 行尚未执行。
   迁移不删除/重建 journal、不改请求或目标摘要，另加单调约束禁止将 started 改回 0。
5. `cancel` 与登记/启动/完成使用相同日志写事务，避免终态已提交后取消又尝试改写不可变记录。
   终态取消是幂等读取，不改变既有成功/失败事实。

## 第一轮自审：身份与外部效果

- 登记本身没有 PostgreSQL 管理连接或恢复副作用；目标仍由部署配置计算，不接收任意任务 URL。
- started 标记先落盘，恢复后落证明；这个顺序留下的崩溃窗口只会保守中断，不会重复恢复。
- 单独的登记与派发不构成跨数据库原子提交；持久控制 continuation 和幂等重发承担恢复责任，
  不能将内存线程或一次 spawn 响应当作持久派发完成。
- 预先取消只能在 started=0 时免去外部停止观察，已启动记录绝不能使用该捷径。

## 第二轮自审：迁移、竞争与证据

- journal 迁移在 BEGIN IMMEDIATE 内检查列并 ALTER，两个初始化者串行化，旧记录默认 started=1。
- 先取消、先启动及终态后取消均按日志事务顺序裁定；取消不会重开终态或让已登记请求换绑定。
- SQLite 专项覆盖登记后重启、提前取消、错误绑定、started 单调性和旧 journal 保守迁移；
  原生 PostgreSQL 验证登记不创建库，提前取消甚至不连接不可用管理端点。
- 不新增控制面迁移、不重启试用服务；这些测试仍不是完整 DR 派发或跨区域恢复验收。

## 实施核对

私有 journal 的 started 升级与单调约束、取消标记不可回退、无外部效果的 register、首次
启动准入、提前取消捷径和取消事务串行化均已实现。58 项恢复执行/登记测试通过，包含
8 项原生 PostgreSQL 测试；最终加强取消单调约束后，登记专项 8 项再次通过。独立记录见
`docs/testing/PRD-111-restore-registration-20260911.md`。

下一步仍是控制面真实 DR 派发、结果绑定及实际阶段证据接入。本实施单元没有把恢复产物
提升为生产数据库，也没有替代跨区域对象/KMS、writer fencing、路由 ACK 或 RPO/RTO 验收。
