# 使用者用量、预算与内部账本浏览器补齐

沿用 S2 使用者归集和内部账本/预算两份设计及其自审，不改变平台商业账、应收或员工登录边界。本轮补足之前只有 API 与渲染夹具、缺少浏览器真实提交的部分。

## 第一轮自审

- 复用隔离注册/组织/使用者/KEY 的既有流程和数据库基线，增加显式 finance 流程选择。默认组织验收不改变，不重复执行无关的初始化导航和动画检查。
- 浏览器通过正式页面完成预算创建、修改、耗尽模式切换、调整、冲正、用量筛选和 CSV 下载，再从真实 API 与数据库核对结果。三个视口为 390、1280、1440，不把渲染夹具当真实业务提交。
- 用量需要非空归属与多币种证据；在隔离数据库复用已有 API 测试用量夹具，明确记录 fixture 来源，不能声称这些是模型真实调用。夹具入口只由验收脚本显式注入，默认不存在，要求 loopback 和临时随机凭据，目标限定本轮新注册的组织，不出现在生产服务或资产中。

## 第二轮自审

- 夹具只能写 `.tmp` 本轮 acceptance.sqlite3，不能指向用户数据；同组织重复请求不产生重复测试用量。禁止读取用户配置和模型 KEY。原始记录及 CSV 不写入浏览器 Storage。
- 断言六位小数、原币分列、两名使用者筛选隔离、KEY 轮换/员工停用后历史归属不变。冲正结果净额必须归零，并保留原始借记；不是删除分录或重算历史费用。
- 预算创建与更新要通过真实状态变化确认，不仅检查 200；对话框草稿取消、再次打开和离页后必须清空。所有读取与提交仍走现有权限和 CSRF，夹具不替换任何业务鉴权。
- 浏览器失败保留截图和安全诊断，不放宽字号与布局断言。批次只跑受影响单元及联合浏览器；SQLite/PostgreSQL 的既有权限、并发和回滚证据在代码未变时复用，产品修复后只补受影响用例。

完整 provider 到 Gateway 调用和计量的链路、规模性能、三浏览器、多 DPR/Linux、平台历史计量受控恢复及后续 Excel 领域仍需继续完成，不由本次验收替代。

## 控件可读性复核

第一轮：真实截图中用量筛选动作按钮仍使用浏览器小字号，仅调整该容器下按钮为 16px、最小 40px 高度。第二轮：动作区允许换行，不缩小文字适配窄屏；生产包验收直接测量按钮字号。预算表单的 1000 是空白金额输入的占位提示，不能误判为已保存规则被重置。

## 夹具失败复核

第一次真实运行在夹具接口返回 500：查询错误引用不存在的 `workspaces.slug`，尚未执行财务页面操作。修订为通过 `organization_profiles.slug_normalized` 识别本轮组织，同时限定 `organization/user_created`。第一轮复核补上路径和临时凭据的显式异常检查，避免优化模式绕过 assert；第二轮复核将三条合成用量放入同一事务，以锁串行化同组织重复请求，失败全部回滚且可重试。复用的 API 测试 `_usage` 仅增加可选外部事务，原调用继续自行提交，不改变生产服务。

候选 index 首次运行发现测试引用尚未提交的反馈连接池 helper。第一轮复核确认只有用量/财务撤权模拟依赖它，生产财务不依赖；第二轮改用已提交 `database_request_scope(reuse_connections=True)` 建立独立请求作用域，退出即回收并恢复外层上下文。保留真实撤权更新、提交和响应拒绝断言，不拉入反馈连接池业务改动、不跳过测试。该两处测试支持文件随 PRD-147 联合验收脚本提交，实际用量/财务业务仍分别属于 PRD-099/144。
