# 项目 KEY 生命周期与财务归属

状态：当前产品决定（2026-10-05）

MetaHub 当前采用简单、可解释的项目 KEY 模型：一名员工的一把个人 KEY 在同一时刻只绑定一个项目，可选绑定该项目下的一个应用。员工参与另一个项目时，管理员把原 KEY 改绑到新项目，员工继续使用同一把 KEY，不需要修改第三方客户端配置。

个人 KEY 只有在员工同时加入 active 项目和 active 应用后才是“已启用”。刚创建但尚未分配的 KEY 显示为“待分配”，不能调用但仍占用该员工唯一的 KEY 名额；员工删除后才释放名额。删除只撤销凭证并隐藏个人目录记录，账单、用量和审计历史保留。

## 生命周期

- 项目处于活动状态时，绑定 KEY 可以调用。
- 项目停用或归档时，系统立即停用该项目下的 KEY；停用原因记录为“项目已停用”。
- 把 KEY 改绑到活动项目时，系统关闭旧绑定区间并建立新绑定区间；如果 KEY 只是因旧项目停用而失效，则自动恢复使用。
- 管理员手动停用 KEY、移除成员导致的停用不会因为改绑而自动恢复，必须显式重新启用。
- 移除成员仍然会停用该成员创建或持有的全部 KEY，并保留历史账务引用。

## 财务与用量口径

每次请求在入账时保存项目和应用快照。历史账单、用量、预算消耗和导出结果只使用请求发生时的快照，不根据 KEY 当前绑定回写历史记录：

```text
改绑前的请求 -> 旧项目
改绑后的请求 -> 新项目
```

系统同时保存 KEY 的绑定时间段，供管理员查看何时从哪个项目切换到哪个项目。KEY 当前归属只用于后续请求鉴权和预算准入，不能作为历史账务的回溯依据。

## 当前范围

暂不支持一把个人 KEY 同时属于多个项目，也不要求第三方客户端增加项目 Header 或切换 Base URL。应用服务 KEY 仍可以固定绑定单一应用；多项目预算池和多归属个人 KEY 作为后续产品能力单独设计。
