# S3 外部任务的阶段续接

日期：2026-09-11。范围：PRD-106 共享任务能力，供 PRD-111 实际恢复接入。
状态：两轮编码前自审完成，共享阶段能力及调用方回归已验证。
承接 `S3-durable-restore-lifecycle-20260910.md`。

## 设计

1. 外部恢复成功只提交恢复阶段事实，不能调用 `finish` 提前结束整个 DR 根任务。
   在 `ExternalJobContext` 增加 `commit_effect`，沿用任务级 effect key 和内容摘要幂等规则，
   在同一事务中写业务变更与 effect。等待记录、原始 continuation、根 attempt 和 generation
   保持不变；只有最终阶段才使用已有 `finish`。
2. 每次阶段提交必须验证当前 resumption lease、根 job/attempt/generation 和外层调度 fence，
   在回调前后检查真实数据库时间、取消和外部总截止时间。失去任一条件则回滚全部阶段写入。
   取消/超时只拒绝新阶段，不自动终结尚未确认停止的外部执行。
3. 普通执行和外部续接共用 effect 的查询、摘要比较和插入函数。已提交阶段重放返回 False，
   不再次执行回调；同 key 不同摘要拒绝。重放也在提交前重新校验所有权和截止时间。
4. 阶段回调只允许短数据库事务，不执行网络、恢复子进程、DNS 或其它不可回滚外部操作。
   DR 后续将“真实执行观察 → 绑定校验与证明持久化 → 后续阶段”分开；不能把调度 effect
   或恢复指纹当作 Gateway ACK、生产 writer fencing、KMS 跨区域恢复或账本守恒证明。
5. 复用现有数据库表与约束，不新增状态或迁移，不修改试用 schema 0150。
   本实施单元不声称 DR 已经接入、已切换生产数据库或已完成 PRD-111。

## 第一轮自审：原子性与身份

- 根任务的唯一 effect key 跨租约代数生效；提交时记录当前根 generation，不使用 resumption
  generation 作为业务幂等身份，避免接管重做业务变更。
- 锁住根 job 的 live 查询串行化两个提交者；旧租约即使持有旧 continuation 也不能再写。
- 复用的 effect 内部函数不提供独立授权能力，调用者必须在同一事务内做前后 fence 校验。
- 不能从根 `PlatformJobContext` 借用普通 lease；外部等待已经释放该 lease。

## 第二轮自审：取消、崩溃与敏感边界

- 回调后崩溃且未提交：业务和 effect 都回滚。提交后响应丢失：新 observer 重放读到同一
  effect，不重做回调，也不增加根 attempt。
- 取消在恢复阶段与后续阶段之间发生：拒绝新业务阶段，保留等待供 runner 停止确认；
  不因本地观察失败使用普通任务失败路径把外部工作遗弃。
- 即使是幂等命中，也不能越过已经失效的租约、截止时间或外层 fence。
- `platform_job_effects` 只存摘要和固定 key，不存 value 原文；原始异常由已有外部观察器
  转为固定安全错误。新增专项覆盖 SQLite 原子性、重放、摘要冲突、取消、截止、接管，
  以及真实 PostgreSQL 时钟过期和并发，最后核对敏感标记未进入公开任务投影。

## 实施核对

`ExternalJobContext.commit_effect` 已复用普通任务的原子 effect 逻辑，并保留独立的前后租约、
取消及截止时间校验；普通任务的幂等命中也补上提交前校验。没有新迁移，没有改变原始等待
绑定，没有使用普通任务租约继续外部任务。专项测试见
`docs/testing/PRD-106-external-phases-20260911.md`。

后续 PRD-111 仍需：先持久登记执行再派发，绑定真实恢复结果，阶段提交恢复证明，再在独立
验证通过后处理路由等后续阶段。当前 DR runtime 尚未使用本能力，不得宣称端到端容灾完成。
