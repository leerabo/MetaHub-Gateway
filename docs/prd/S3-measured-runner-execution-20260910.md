# S3 真实容量执行设计

状态：两轮编码前自审完成，执行器实施中。承接 PRD-106..113 批次，不修改已发布试用入口。

## 数据与执行

runner 拥有独立 SQLite 状态卷，不读取 Control 数据库或共享配置。闭合的签名 permit 仍只包含
目录 code、对象、环境、region、规模和时限。目标、合成身份、资源探针及凭据文件由部署配置白名单提供，
不能通过 API 填写 URL、路径、脚本、环境变量或命令。

提交事务按 object_id + 稳定 execution digest 幂等；同对象不同参数冲突。
状态为 queued/running/stopping/succeeded/failed/cancelled/interrupted，取消及 kill generation 持久保存。
独占进程锁保护单 runner worker；只有取得锁的新进程可以把旧 running/stopping 记录改为 interrupted，
不得自动重新施压。进程退出前停止产生请求并回收所有执行线程。重复提交终态任务只返回原结果。

permit 的 expires_at 是最晚启动时间，不是已经启动的固定时长运行的心跳租期。
领取和发起测量前都检查到期时间；排队过期持久记为 failed/runner.permit_expired。
新签名仅允许查询或取消已有执行，不能通过重复提交复活过期执行或刷新排队授权。
取消先于提交到达时，按相同执行摘要持久写入 cancelled，迟到提交只能读到停止结果。

HTTP 提交可以返回 202 状态，独立的签名 status/cancel 请求不消耗初始 permit。
Control 后续按持久检查点安排下一次轮询，不能用一个同步 HTTP 请求等待 72 小时，
也不能把 pending 当作业务失败或耗尽普通失败重试次数。该跨域适配独立验证后接入。
现有 platform_jobs/attempts 具有 20 次计数约束，load_test_runs 的初始 job_id 不可变。
不能仅让 HTTP 客户端接受 202 就宣布接入完成，也不能把根任务成功伪装为业务完成。
本次先验证部署执行器和签名异步查询协议，持久调度及取消联动仍是发布前必需项。

## 实测负载

使用 httpx 有界连接池，固定 Gateway chat、Control session、公共 status 场景。
真实记录完成请求数、成功/限流/不可用/异常、延迟直方图、有效吞吐和每个合成主体的成功计数。
直方图、身份计数和资源采样采用有界结构，不能随 72 小时时长线性保留响应或请求记录。
不读取/保存响应正文，不接受重定向，不使用环境代理，请求截止时间和并发由部署上限限制。

资源指标来自白名单探针对目标进程的实际测量，不用 runner 自身资源冒充 Gateway/Control 资源。
探针绑定目标进程 PID + 创建时间，资源采样不包含命令行、环境、连接地址或路径。
探针丢失、进程换代、计数回退或不足采样均不能生成成功基线。
初始和结束采样用于资源变化，连续采样用于峰值及后续长稳判断。实测数据摘要不是真实性证明的替代品。

取消状态只证明 runner 停止产生/等待自身请求，不宣称所有目标服务下游副作用均已撤销。
真实混沌需要单独部署、可幂等撤销的故障适配器和恢复证明；未配置适配器时明确不可用，
不得通过人为修改统计值制造故障结果。

## 第一轮自审：授权与真实性

- P0：API 指定任意目标会产生 SSRF。目标仅部署白名单，使用明确的私网/环回 IP，不跟随 DNS 或重定向。
- P0：单 KEY 伪装多租户会失真。配置保留独立合成主体和凭据引用，重复身份或凭据拒绝；
  最终 100+ 租户验收仍必须结合 Gateway 权威身份事实，不以配置条数证明真实租户隔离。
- P0：目标资源不可观测时不能用固定值填补。资源探针失败关闭，明确目标进程代次和采样。
- P1：持久状态不得保存测试密钥。仅保存签名参数事实、安全状态、摘要和聚合，密钥按部署文件读取。
- P1：共享配置或 Docker socket 会扩大权限。runner 不挂载 Control 数据和主机管理接口。

## 第二轮自审：并发、停止与恢复

- P0：进程重启重试可能重复施压。独占 OS 文件锁和持久状态共同保证旧执行不自动重跑。
- P0：取消与完成竞态会把停止记录改成成功。最终提交在同事务重验持久取消/kill 条件。
- P1：HTTP 超时不能丢失执行状态。客户端通过同一对象和参数绑定重新查询，而非创建另一任务。
- P1：无限样本保存导致长稳自身泄漏。延迟用有界直方图，资源轨迹保留分层聚合，禁止正文。
- P1：声称取消已恢复所有依赖不成立。区分请求停止、故障撤销、服务恢复三类独立证据。
- P1：无目标配置时不能自动对当前试用服务施压。保持不可用，验收只运行独立合成目标。

## 验证责任

### 基线质量补充及两轮自审

初始基线除至少 100 个样本外，还需满足当前区域服务的 p95 SLO、错误率不高于 100bps、
成功吞吐至少达到目标的 80%、公平指数至少 0.95，且没有失控降级。100bps 和 80% 采用现有
回归比较的误差预算与吞吐容差，后续可由版本化场景策略替代，不接受客户端随意放宽。
第一轮自审：全部 503、无成功吞吐、目标服务 SLO 缺失均不得建立首条基线。
第二轮自审：已有基线时质量恶化仍应判为回归并阻断发布，不能因为统计结果“执行成功”清除旧阻断。
不足 100 个样本保持低置信状态，不清除旧阻断。完成测量不等同于服务健康或 72 小时无泄漏。

本阶段验证真实 HTTP 请求/计数/延迟、状态持久化、并发幂等、参数冲突、取消后无新请求、
重启无重复执行、资源进程换代拒绝及敏感信息不落库。随后接入 Control 轮询、实际 Gateway
合成身份与故障适配器，再做 S3 整批验证；不修改 Excel 完成状态，不提前宣称 72 小时通过。
