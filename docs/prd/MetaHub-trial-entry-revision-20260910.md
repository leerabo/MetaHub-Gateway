# 试用入口修订

日期：2026-09-10。范围：首页、登录首屏、组织创建。根据用户本轮试用反馈修订，
不改变注册策略的平台归属，不将组织 Owner 提升为 SaaS 平台管理员。

## 首页

删除重复口号、编号和标签；首屏保留品牌、一句介绍、登录及创建账号入口。
正文 15-17px，能力标题 18px，展示标题与正文分别设计，不使用全局放大覆盖。
能力区为无外框的八项网格；沿用本地 Three.js 网关场景，不引入 CDN、第三方请求或凭据。
移动端保留能力区露出、动画暂停、减少动态效果和无 WebGL 时的静态回退。

## 登录

品牌请求与控制器 mount 独立启动；mount 同步渲染可用表单，然后恢复已有会话。
用户输入会使旧会话请求失效；品牌更新只替换品牌节点，不替换表单、密码或焦点。
登录、注册、退出与风险挑战继续使用同一代次取消机制，不降低后台认证要求。

## 创建组织

首要表单只填写组织名称，支持中文。后端兼容原显式 slug/region/service_mode 请求，
同时接受只包含 kind/name 的组织创建请求。仍拒绝未知字段、空值、非法显式配置和越权身份字段。

- 标识缺省时，在首次创建事务中由 Workspace 随机 ID 派生 `org-<32 hex>`。
- 区域缺省时使用部署批准列表的第一项；缺省本身进入请求指纹，实际区域只在首次创建时解析。
- 服务模式缺省为 `internal_only`。前端不再伪造华北/华东机房选择。
- 同一幂等键及同一请求始终返回原组织；调整部署区域列表顺序不改变原创建结果。
- 无数据库迁移，无资料清理，不修改已有组织的标识、区域、模式、成员、凭据和余额。

服务区域是部署/数据驻留的配置维度，不是用户所在城市，也不代表模型供应商地址。
本地单机存储不构成多地域部署承诺。内部/对外是服务用途分类，内部指团队员工及应用，
对外指面向客户的服务；组织的这个字段不是互联网访问开关，也不能替代网关鉴权、
网络边界或对外服务合规配置。内部使用同样可以接入 Kimi 等外部模型供应商。

## 自审

第一轮：确认实际阻塞来自品牌等待链和先检查会话后渲染；移除表单中不必要的技术字段，
保留兼容接口和平台/组织权限边界。

第二轮：核对生成随机标识的时机、区域缺省的幂等指纹、品牌迟到时的 DOM 更新、
会话探测晚到与用户输入的竞争。以现有单事务创建、请求锁和代次取消机制实现，
不引入新的身份、凭据或数据库抽象。

## 试用追加反馈

首屏移除 640px 高度上限，按视口扣除导航高度排版；底部仅保留完整的 28px 产品能力入口，
能力标题位于下一屏。保持原有字号，不做全局缩放。

创建组织后的快捷入口只执行组织创建、显式切入新组织、验证 WorkspaceSession 三个请求；
目标控制台独立复核身份、导航权限与版本，验证前不展示私有数据。失败或取消不能跳转，
不提前加载成员、引导、财务等目标页面数据。创建多个组织时也明确切入刚创建的组织。

组织资料主表单仅保留名称，部署区域、服务范围、默认环境收进默认关闭的只读系统信息。
不把区域或服务范围变成组织可任意修改的配置；类型、资料确认状态不再重复展示。

主动切页写入浏览器历史，同页点击不重复追加，初次默认路由规范化仍替换当前条目。
子页面提供返回空间首页入口，优先回到“开始使用”，后端未授权时不生成入口。
账号页、控制台从 BFCache 恢复时重新加载并校验 Cookie，不能复用 pagehide 已销毁的状态。
账号页附加数据分批读取，每批最多三个领域，避免通知、账单等请求集中排队；
每批前检查账号请求代次，注销或换空间后不再启动剩余批次。

追加自审一：确认新组织 Owner、CSRF、幂等、取消、过期与权限复核边界不变。
追加自审二：检查默认路由历史、缓存恢复、直接审批链接、手机返回入口及资料保存后的重入。
