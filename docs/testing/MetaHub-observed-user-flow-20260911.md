## 操作原则

使用 computer-use 技能推荐的浏览器接口，先观察实际截图、标题、按钮与状态，再决定操作。功能路径与用户找路分别核对；根据源代码知道的路由不能作为入口可发现性的证据。仅使用本地合成体验验收账号和组织。没有发送邀请邮件、操作真实业务组织或发起付费模型调用。

## 实际界面走查

1. 首页点击登录，表单直接出现；已有账号进入上次组织的控制台。
2. 返回空间首页查看四个接入步骤，依次检查模型服务、可用模型、路由、员工和接入信息。服务端报告的缺口保持可见。
3. 刷新空间首页后保留账号、组织和所在步骤。未复现此前旧登录页，但不能证明历史偶发失败已消失。
4. 员工页初次读取失败，按页面重试后恢复。页面脱敏日志为 `MetaHub resource load failed virtual-keys TypeError Failed to fetch`，没有可用 request_id。没有将重试成功记录为根因修复。
5. 添加“流程验收员工0911”及测试部门，无邮箱和密码字段。创建档案后自动选中员工并给 KEY 命名。
6. 创建测试 KEY 复现重复创建表单仍展开的问题；修复后再给既有合成员工“测试员工甲”发放 KEY，只选择员工即可完成，名称自动生成，创建表单自动收起。
7. 一次性明文仅在本地测试页面出现，工具输出过滤明文，随后使用隐藏按钮关闭。测试记录不保存 KEY。
8. 接入信息优先展示地址、个人 KEY 使用说明、模型名称和接口类型，SDK 示例折叠；明确 loopback 地址仅限本机试用。
9. 点击账号设置，先显示账号设置加载态，再显示安全设置，没有先显示登录表单。退出后返回新版公开首页。
10. 第二轮按首页服务状态链接访问状态页，内容正常显示；回到首页登录后，根据页面的“模型服务待接通”入口进入配置。厂家选择 Kimi 后，自动标识和名称等配置不占据主表单。
