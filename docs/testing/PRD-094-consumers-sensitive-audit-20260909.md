# PRD-094 使用者增量敏感审计

## 范围与结论

审查消费者 DTO/路由/服务、Virtual Key 发放/轮换、Gateway 认证、0148/0155 迁移及前端新增目录。动态敏感负例见独立测试记录。32 个指定源及证据文件已通过 UTF-8 与高置信度凭据模式扫描，0 命中，原始报告 `.artifacts/g6-security-20260907/prd094-consumers-worktree-audit-1788942919141.json`；它是当时工作树的快照，不是整仓最终敏感扫描或独立提交审计。

- 使用者仅姓名、部门和稳定 ID，没有邮箱、密码、账号或 Membership；DTO 拒绝租户、角色和登录字段。
- 平台角色不是组织管理员。目录要求组织 admin 及 user.manage，读写分别要求 KEY read/write；Workspace 授权在资源事务中逐次复核。普通 developer 仍可维护原有技术 KEY，但不能管理目录或发员工 KEY。
- KEY 只持久化哈希和前缀，创建/轮换明文只在本次响应；认证不信任调用者自报 consumer_id。员工姓名/部门不进入消费者审计摘要。
- 关联由复合外键绑定租户，不可改绑或物理删除；使用者禁用在每次 Gateway 鉴权查询权威表生效。轮换使用单调 revision CAS，旧 KEY 不复用。
- 消费者和 KEY 响应禁止缓存，前端不存入 Storage。渲染转义姓名、部门和 ID；页面沿用空间切换、迟到响应与一次性秘密清理机制。
- 真实 HTTP 测试秘密仅在内存中使用，输出只含状态及测试标识；未使用或展示用户的 Kimi KEY，付费模型调用 0 次。用户浏览器会话未被替换或撤销。
- 两份保护测试库 SHA256 未变：`572173FBF10027815EA1E1ECBDD201D3B7084F6335A86E436A762A68945F3DB6`、`DB52801FDC6B2D0478F3E16DA432DB79F1E88C0FA81A176EA4251A0620CAFE99`。

## 残余风险

KEY 持有人可以代表该身份调用，因此日志证明的是凭据归属而非现场操作人。基础使用者目录不是企业 SSO；SSO 绑定、组织级费用归集及分币种报表仍需独立实现与验证。既有租户删除清单缺失表的问题不能因本次新增两表登记而被宣称解决。

## 真实浏览器补充

本次隔离完整开通证据为 `.artifacts/s1-browser-6y8nim3f/acceptance.json`。浏览器 profile、账号和数据库均独立，未读取用户 .env 或使用用户 Cookie；密码及 KEY 随机生成。验证码确定性随机源仅替换隔离 registration_policy 模块的字符选择，不改变会话与密钥随机源，不解答真实试用或第三方挑战。
