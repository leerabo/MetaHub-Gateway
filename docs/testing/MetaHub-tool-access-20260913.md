# 员工跨工具接入复核 · 2026-09-13

员工使用同一个网关服务及个人 MetaHub KEY；不要求注册 MetaHub 或填写一整页环境变量。客户端要求模型名称时仍需选择或填写。工具必须允许自定义接口，协议转换通过不等于第三方完整 Agent 工作流已通过。

## 本轮修复

- 本机直接 HTTP 核验：`/responses`、`/models`、`/messages`、`/chat/completions` 返回 404；`/v1/responses` 和 `/v1/models` 返回匿名鉴权 401。根入口在源码中存在且不进入 OpenAPI，不能仅凭 OpenAPI 的缺项判断是否已经加载。
- Codex 配置从根地址改回当前生效的 `/v1` Base URL。各工具卡片提供各自地址的复制按钮；Claude Code CLI 使用去掉末尾 `/v1` 的地址，让客户端追加 `/v1/messages`。保留反向代理前缀。
- 移除首屏网关根地址的复制按钮，避免员工把服务标识直接当成适用于所有工具的 Base URL。交付说明同时列出工具需要的地址格式，同一把个人 KEY 保持不变。
- SDK 示例继续默认折叠；按官方文档保留 Codex 配置文件和 Claude Code CLI 个人设置示例。模板只含公开地址、模型名称和 KEY 占位，不读取或存储真实员工密钥。
- 接入信息首屏改为“员工交付规则：一个网关地址＋一把个人 KEY”：管理员已配置默认路由时，员工只接收统一 MetaHub 网关网址和个人 MetaHub KEY；模型名称只在工具强制要求时填写。工具卡片中的 `/v1` 或协议路径只是同一网址的技术格式，按客户端需要自动派生，不代表另一项服务或另一把 KEY。环境变量/配置文件明确标为客户端保存地址与 KEY 的方式，不再作为员工必须填写的配置步骤；工具卡片仍保留协议差异和未完成的 Agent 联调边界。
- 本轮没有重启 Gateway、Control 或 Console，也没有改变用户浏览器页面。
