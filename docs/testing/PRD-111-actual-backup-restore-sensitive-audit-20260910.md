# PRD-111 实际恢复敏感审计

日期：2026-09-10。范围仅为本轮共享备份恢复、原生适配器和 PostgreSQL 0160 修订。

## 数据边界

- 快照中的真实业务值仍由既有 envelope AES-GCM 加密保存，新 manifest 通过摘要绑定到 AAD。
- 新增投影只包含表名、组件、行数、结构摘要和内容摘要；测试确认受检行值、归属 ID、正文和
  配置值不出现在恢复结果或存储 envelope 明文。摘要不是匿名化数据导出的授权。
- 原始数据仅在隔离文件/数据库和读取进程内用于恢复验证；临时 SQLite 文件和 dump 文件由适配器释放。
- 测试只使用合成账号、种子、KMS 和对象服务，没有调用付费模型或读取真实业务备份。

## 目标和执行

- PostgreSQL URL 使用结构化解析，拒绝 host/dbname/user/service/options 等 query 覆盖。
  数据库名不能变成另一条连接串；本地别名、默认端口和百分号编码不能绕过源库身份检查。
- 新备份绑定源服务地址/端口/数据库名的摘要，在源库离线时读取目标实际身份比较；目标还必须为空。
- 恢复独占锁覆盖实际子进程与数据复核。不运行 --clean，不删除已有库/表，不自动回切。
  恢复失败路径和竞争用例已验证释放锁。新执行必须获得新空目标。
- 子进程清除继承的 PG/METAHUB 配置，只恢复显式连接参数；密码不出现在命令行，返回固定错误码。
  对象读取失败也会关闭响应 body，不返回 provider 原始错误。
- 0160 仅修改明确白名单中的 47 个既有兼容函数。固定 pg_catalog 优先，pg_temp 最后；不更改权限，
  不修改第三方函数、不改既有迁移正文；保存原搜索路径并验证回退保护。

## 检查结果

- 本轮两个产品 Python 文件、两个测试文件和最终 JUnit 报告未匹配 API key / private-key 模式。
- 47 个最终专项用例无失败、错误或跳过。无新前端、API 公开字段或角色权限放宽。
- 提交范围不包含 .env、数据库、备份文件、原生集群、日志、截图、密钥和未完成的试用 UI 改动。
- 试用 5173 / 8001 仍为 PID 11248 / 17220。本轮没有线上迁移、重启或删除保留证据。

## 残余风险

备份 payload/envelope 仍沿用既有全量内存模式，尚未完成大规模流式处理验证。
函数固定搜索路径对执行计划的影响需进入 S3 整批性能门禁。恢复目标应由部署侧限制其他写入者；
advisory lock 不替代数据库权限或网络隔离。长外部任务的取消、超时、接管及停止确认仍需接入持久
runner。本地 test KMS 与内存对象服务的用例不能证明真实云端 KMS、S3 或跨区副本安全。
