# MetaHub 用户可见路径复验

日期：2026-09-11。接续原真人路径报告，本记录只统计本轮新增修订与验证。

## 方法

使用 computer-use 技能推荐的浏览器操作接口，实际观察截图、点击可见按钮、填写表单、
操作浏览器后退和退出。先完成现有主线检查，再以“接入已有兼容网关”的普通管理员目标
重新走首页提示。没有用手写内部路由或后台 API 代替本轮自然路径。
代码和自动化测试仅用于定位、修复及故障边界验证，不充当真人可发现性的证据。

## 本轮修订

- U39：自定义服务基本表单只保留名称和地址，内部标识自动生成；特殊协议、认证、备注
  按需展开。自动标识在不确定失败后的重试中保持一致。成功后展开刚创建服务的密钥配置。
- U40：模型服务关闭状态只有一个密钥入口；再次点击可收起。密钥读取失败显示在折叠区外。
  收起仍清空未提交的明文，不把凭据保存在草稿或报告中。
- U41：模型、路由和接入信息复用组织首页的服务端任务事实，明确接入缺口及可执行入口。
  前置条件未完成时，补配置是主操作，后续配置保留为普通入口。接入页可刷新状态，
  只有服务端已有成功调用事实才显示“已记录成功调用”，刷新本身不调用模型。
- U42：运行环境或模型依赖的加载中、失败、空态显示在路由折叠区之外；给有权限的管理员
  提供配置入口，不再让管理员猜测禁用按钮的原因。

## 实际浏览器结果

使用既有“体验验收管理员”和“体验验收组织 0910”，没有操作用户原有业务组织。

1. 从公开首页登录既有合成账号，进入上次工作页，再按返回空间首页进入四步接入。
2. 沿页面入口经过模型服务、模型目录、模型路由、员工与 KEY、接入信息。
3. 在自定义接入只填写“界面验收兼容服务 0911”和服务地址，实际添加成功；没有填写 Code。
4. 创建后对应厂家 API KEY 输入框自动展开并获得焦点，其他服务的密钥区保持关闭。
5. 输入不含权限的合成草稿，收起再展开；DOM 确认输入为空且仍为 password 类型。
   没有点击保存密钥，没有真实厂家密钥或员工 KEY 写入。
6. 本轮新建的无密钥服务随后已停用，保留验收记录；没有删除既有记录。
7. 模型、路由、接入信息均实际显示“模型服务待接通”。补配置主入口可返回模型服务页，
   页面不再把后续步骤误示为当前下一步。
8. 点击刷新接入状态，出现忙碌状态并恢复按钮，缺口仍如实显示，连接资料保留。
9. 390x844 手机检查路由、接入资料、自定义服务及高级设置，无遮挡。路由文档内容宽度
   与可用视口均为 375px，列表与父内容右边界均为 366.33px。
10. 1440x900 桌面接入资料文档宽度与可用视口均为 1425px；状态区和资料区右边界
    均为 1272.33px，与父内容区一致。默认桌面也检查了模型页和自定义服务表单。
11. 浏览器后退从服务页回到接入资料，组织上下文保留。恢复默认视口后退出验收账号，
    实际显示退出过渡并返回新版公开首页。
