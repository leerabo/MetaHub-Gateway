## 观测范围

连续采样使用冻结源码、独立最新迁移数据库、随机进程内测试凭据和随机 loopback 端口。
Control/Gateway `/health` 与 Console 页面均为真实 HTTP，不使用 ASGI 或鉴权替身。
它只补充连续可用性与时间覆盖事实，不独自证明付费、企业治理、私有 Gateway 业务长稳、
四波试点、生产容量、无 P0/P1 事件或产品/SRE/安全/测试/财务/法务的独立会签。
这些要求必须分别使用真实证据，不自动生成审批或从健康请求推导业务通过。

## 记录与失败边界

- 正式模式的观测下限为 259200 秒。短诊断单独标记 `diagnostic_passed`，不会标记为 72 小时通过。
- 使用单调时钟和首尾真实样本边界，排除客户端准备与汇总时间。跨窗口空档计入最大观测间隙。
- 每分钟 fsync 一条摘要链和原子状态文件。内存只保留当前窗口，拒绝覆盖已有运行目录。
- 任意 HTTP 错误或大于 10 秒的观测空档使该运行失败；失败结果保留，不把多次运行拼成一次通过。
- 防休眠覆盖整段观测。进程/机器中断不自动续计，缺最终成功状态不能通过门禁。
- 正式证据仅保存摘要、计数、时间、错误类别和源码版本，不保存凭据、URL、请求或响应正文。

## 两轮自审

第一轮：不能把进程运行时长当成实际采样覆盖。改为保守的首尾样本边界，并计入窗口之间的空档。
不能让长跑积累数百万内存样本，改为有界分钟窗口。单元测试覆盖时长不足、缺目标、计数矛盾和异常。

第二轮：失败不能被下一次运行覆盖；目录采用独占创建。异常仅记录类型，原始错误文本不入证据。
短诊断与正式 72 小时状态不同，所有输出明确 `ga_approval=false`。用真实 HTTP 200/503 验证
成功诊断、失败保留、持久状态和摘要链。进程级中断由外部检查识别，不通过重启伪造连续性。
