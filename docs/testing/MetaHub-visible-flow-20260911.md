## 验收方法

使用 Computer Use 的浏览器操作能力，从公开首页登录已有合成验收账号，依照可见的
空间首页、配置模型服务、下一步、返回链接操作。先记录页面为何让人困惑，再读代码定位。
为区分故障，另从侧栏打开过同一模型页；这一操作属于诊断，不算自然引导通过。
仅使用独立的“体验验收组织 0910”，没有新增员工、发放 KEY、调用付费模型或改动业务配置。

## 新发现与处理

| 编号 | 用户眼前的问题 | 本轮处理 |
| --- | --- | --- |
| U33 | 已有员工和 KEY 时仍先显示两张空白创建表单，记录在下方 | 添加员工与发放 KEY 按需展开；空目录、新 KEY 或刚添加的员工仍自动展开相应步骤 |
| U34 | 部门没有说明是否必填 | 明确标记可选，不增加邮箱或密码 |
| U35 | KEY 的环境依赖失败时，只见不可用提交按钮，原因藏在高级设置 | 错误和重试显示在折叠区外；区分加载中、失败、确实没有环境 |
| U36 | 模型与 KEY 窄版列表隐藏表头后，值失去字段语义 | 增加仅在紧凑列表显示的字段标签，不暴露内部生成 ID |
| U37 | 从首页点击配置模型后突然回到无说明的登录页 | 修复跳转丢弃提示和请求编号的问题；只接受固定提示和有界请求编号，不将任意后端错误写入 URL |
| U38 | 表单折叠后，员工区仍保留大表单间距 | 收紧空白，折叠入口并列；展开时占完整宽度，不缩小字体 |

修订检查：折叠只影响展示，不保存数据，不改变授权；同一 DOM 内收起再展开保留普通草稿。
一次性 KEY 明文仍按原有逻辑清理，登录边界仍销毁业务状态；没有放宽 Cookie 或权限校验。
缺少前置配置时不能假装完成。运行环境错误必须保持可见，不藏进折叠表单。

## 浏览器复验

- 已发布版本实际打开员工页，已有 KEY 首屏可见，不再先展开两张空白表单。
- 展开发放表单，选择已有测试员工，KEY 名称自动带出；收起再展开，选择和名称保留。
  随后清空草稿，没有点击创建 KEY。
- 390x844 手机视口下打开添加员工，只有姓名和可选部门，控件没有遮挡。
- 手机文档可用宽度及内容宽度均为 375px；KEY 列表和父内容右边界均为 366.33px。
- 1440x900 桌面下文档可用宽度及内容宽度均为 1425px；KEY 行与父内容右边界均为 1272.33px。
- 根据下一步进入接入信息，首先显示网关地址、个人 KEY 提示、模型名称及接口类型；SDK 示例折叠。
- 浏览器后退回到原员工页，组织上下文保留。
- 最终宽桌面模型目录截图确认标签与值匹配；恢复默认视口后实际点击登出，
  显示退出过渡并回到新版公开首页，未保留验收账号登录态。

尺寸改变后第一次截图曾只捕获局部宽度，稳定后的完整截图正常；未将该自动化捕获现象
归因为应用布局缺陷。一次 DOM 定位超时后重新观察页面，页面仍正常，未宣称该次量测通过。
