## 核验

1. 登记及重复登记不恢复数据、不创建目标，进程重启后可以进行首次恢复。
2. 先登记再取消、登记时直接取消，两种顺序都持久保留取消；迟到登记/派发无法启动恢复。
3. 先成功后取消不改写终态；同执行 ID 更换 job generation 在派发前拒绝，原请求不受影响。
4. 数据库约束拒绝撤回取消、started 从 1 回到 0，以及提前取消后把 started 改成 1。
5. 使用测试专属日志还原旧版无 started 列的结构；两个初始化者并发升级，旧 running 行
   一律默认已开始，重启后只确认中断，不重跑或覆盖实际恢复文件。
6. 原生 PostgreSQL 登记后不存在恢复库，首次派发后真正恢复并关闭准入；提前取消的执行
   不进入 PostgreSQL 管理连接入口，即使配置的是未使用的本地管理端点，也不创建目标库。

测试全部使用新建隔离数据。没有控制面迁移、试用服务重启、真实付费模型调用或生产库提升。
本记录不是端到端容灾、跨区恢复、路由 ACK、防脑裂或 72 小时稳定性验收。
